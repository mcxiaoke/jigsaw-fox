## [2026-09-01 09:55 GMT+8] 运行时脚本：结束/Ctrl+C 时释放 GPU 与 VRAM

**改动**：`scripts/my_comfyui_batch_gen_v4.py`，在 main 末尾 `return 0` 前加一次 `client.free(unload_models=True)`（包在 try/except ComfyError 里，ComfyUI 已挂也不崩）。

**退出路径**：

| 场景 | 行为 |
|---|---|
| 正常跑完所有 job | 底部 `return 0` 前 `free` 释放 GPU + VRAM |
| 单次 Ctrl+C | 跑完当前图后循环 break，仍落到底部 `return 0` → `free` |
| 两次 Ctrl+C | signal handler 直接 `sys.exit(130)`，`SystemExit` 立即抛出，不经过 `free`（此时用户直接结束 ComfyUI） |

**原因**：此前只在大间隔的「周期性硬重置」里 `free`，正常结束/单次 Ctrl+C 退出时 GPU/VRAM 未主动释放，下次启动或切任务时显存仍被占。

## [2026-09-01 09:03 GMT+8] 新增 `--reseed`：把 seed 从 modifier 的 rng 里拆出来

**背景**：用户问"换 seed 是不是才是传统 AI 生图的抽卡"。确认是的，并发现脚本里 seed 与 modifier 是耦合的 —— `seed` 从决定打光/视角/风格的那同一个 rng 里取（`build_jobs` L353），所以**无法只换 seed 不换 prompt**，也就无法区分"这段 prompt 写得差"和"这一掷运气差"。

**改动**：`scripts/my_comfyui_batch_gen_v4.py`

```
--reseed N   每个 prompt 抽 N 个 seed，modifier 固定不变。默认 1。
             总张数 = subjects × rounds × reseed
```

两条路径，默认路径必须与历史逐位一致：

| reseed | 行为 |
|---|---|
| 1（默认） | 走原路径：`seed = rng.randrange(...)`，key 为 `{tag}:{index:04d}`。**与改动前逐位兼容** |
| N>1 | prompt 每个 (tag, index) 只组装一次并复用；seed 取自独立随机源 `Random(f"{tag}:{i}:{base}:r{r}")`；key 加 `:r{N}` 后缀，不与普通批次冲突 |

**顺带暴露的原有脆弱性**：任何 modifier 维度的增删都会洗掉全部 seed，因为 `Random.choice()` 每次调用消耗的随机状态数取决于候选个数。实测对比 v4.0 → v4.1（新增 optics + 改为纯 1:1）：

| tag | v4.0 seed | v4.1 seed | 原因 |
|---|---|---|---|
| Nature:0000 | 4171998325 | 4010062671 | 新增 optics 抽取 |
| Ocean:0001 | 708590383 | 432547431 | 新增 optics 抽取 |
| Landscapes:0000 | 2951195675 | 1784145541 | 新增 optics 抽取 |
| Cities:0000 | 678234534 | 678234534 | 偶发巧合：rng 总消耗次数恰好相同 |

不是回归，但说明耦合设计本身不稳。`--reseed` 用独立随机源后，modifier 怎么改都不动 seed。

**验证**（全 21 tag，`reseed=4`，9120 job）

```
distinct keys        9120 / 9120   无冲突
distinct prompts     2280          每个 prompt 用 4 次
distinct seeds       9120 / 9120   无重复
distinct filenames   9120 / 9120   relocate 用 seed 命名，天然不覆盖
anchor_count 1 vs 2  seed 不变 560/560   prompt 变了，seed 一个没动
```

**附带收益**：相同 prompt 连续生成会让 ComfyUI 命中 conditioning 缓存。此前实测同 prompt 12.2s vs 异 prompt 16.2s，所以 `--reseed` 批次的实际速度通常优于 `--sec-per-image` 的估算值。

**建议用法**：先诊断再放量。

```bash

# 判读：同一 :r0~:r3 组
#   4 张全差 -> prompt（subject / anchor）的问题，改库
#   好坏参半 -> prompt 没问题，靠量筛，加大 --rounds
```

**修改 1：锐度措辞修正（资料纠正了 v4.0 的一处错误）**

v4.0 写的是 `razor sharp from the foreground to the background`，即全图超锐——读起来像重度后期，会让写实图发假，而且会连同自然空气透视一起抹掉。资料给出的区分才是对的：

- **禁** 光学虚化（shallow DOF / bokeh / lens blur / soft focus）
- **允许** 自然空气透视（远景有距离雾才是真实风光照片）

所以锐度改为"一致锐度"+"纵深交给构图表达"：

```
deep depth of field, consistent sharpness across the whole image, depth conveyed
through scale, overlap and perspective rather than optical blur
```

**修改 2：新增两个约束**

- `no excessive sky or water` —— 大片天空/水面是拼图死区最大单一来源（半屏天空 = 半屏同色拼块）
- `no repetitive micro textures` —— v4.0 精简时误删，这次补回。草纹/砂石/树叶类重复微纹理正是让大片区域无法拼合的原因

不是所有题材都给广角——给微距题材强加"广角"和之前锚点踩的是同一个坑。三档分配：

## [2026-09-01 08:44 GMT+8] 提示词库 v4.0：修复卡通化漂移与背景虚化，融入 20 类视觉锚点

**修改 1：风格按题材分池（治本）**

`style` 从全局单池改为 `style_pools` + 每 tag 的 `style_pool` 字段：

- `photo` 池（15 个 tag，配额 1750，占 77%）：Animals / Pets / Nature / Landscapes / Flowers / Ocean / Birds / Cities / Architecture / Food / Seasons / Transportation / People / Sports / Others
- `illust` 池（6 个 tag，配额 530，占 23%）：Art / Cartoon / Fantasy / Holidays / Space / Abstract

photo 池**只用技术型措辞，不用题材型措辞**。初稿沿用了 `wildlife photography` / `architectural photography` 这类题材词，dry-run 立刻暴露错配：海星场景抽到 "architectural photography"、霓虹市场摊抽到 "wildlife photography"——把错误题材注入画面，与 v2.0「冲突元素」是同一个病。已全部替换为题材中性的技术词，并额外排除 `cinematic` 与 `macro`（两者都把模型拉向浅景深，与新加的全焦后缀打架）。

illust 池 6 项全部要求 layered depth / brushwork / texture，主动抬高扁平纯色的到达门槛。

**修改 2：清除虚化指令 + 强制全焦**

9 处 `soft ... blur behind` 全部改写为锐利/分层表述（如 `soft garden blur behind` → `a sharply detailed garden behind`）。Abstract 的 4 处 `a macro of` → `an extreme close-up of`（macro 隐含浅景深）。

`quality_suffix` 新增（全部正向，因为 CFG=1.1 时负向词无效）：

```
deep depth of field, razor sharp from the foreground to the background,
extremely detailed background, ... no large flat empty areas, full-bleed artwork
```

同时精简掉互为重复的措辞（`no out of focus areas` == `deep depth of field`、`no empty corners` == `detail filling all four corners` 等），约束类型一个没少，词数从 85 降到 56。

**修改 3：融入 20 类视觉锚点（对资料做了实质性修正）**

每 tag 新增 `visual_anchors`（4 条，共 84 条），每个 job 注入 1 条，位置在 subject 之后、lighting 之前，让 4B 编码器的注意力集中在「主体+地标」这对上。

**重要偏离**：原始资料列的是具体物件（"海龟壳花纹"、"瓷器花瓶"、"糖果屋糖霜屋顶"）。直接照搬并重跑验证后确认会把物件强塞进不匹配的场景——`water surface reflections` 落到了大象和老虎身上，`sea turtle shell patterns` 落到了龙虾笼上。这正是 v2.0 被投诉的「一个图里四只猫」类冲突元素。因此**锚点全部改写为表面质感/构图特征而非具体物件**（如 Ocean 用 `rippled sand and gravel texture` 而非 `sea turtle shell patterns`），既保留拼图地标（色彩过渡、纹理、对比物），又不注入与场景打架的物件。

**修改 4：视角黑名单（新增，小改）**

`viewpoint_deny`：Landscapes 屏蔽 close-up 与 flat lay，Cities / Architecture / Transportation 屏蔽 flat lay。俯视与特写会压平这些题材依赖的空间纵深，实测影响约 25% 的风景图。

**修改 5：清理冗余 `extra`**

Animals / Pets / Birds 的 `extra` 只是复述 subject 已有的「单一主体」表述（subject 里已写 `one adult elephant as the clear central subject`），白白占用编码器预算，已清空。Ocean / Space / People / Abstract / Cartoon 的 `extra` 携带真实增量约束（填满角落、不聚焦人脸、防扁平背景），保留并精简。
