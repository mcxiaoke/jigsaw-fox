## [2026-09-01 09:03 GMT+8] 新增 `--reseed`：把 seed 从 modifier 的 rng 里拆出来

**背景**：用户问"换 seed 是不是才是传统 AI 生图的抽卡"。确认是的，并发现脚本里 seed 与 modifier 是耦合的 —— `seed` 从决定打光/视角/风格的那同一个 rng 里取（`build_jobs` L353），所以**无法只换 seed 不换 prompt**，也就无法区分"这段 prompt 写得差"和"这一掷运气差"。

**改动**：`scripts/my_comfyui_batch_gen_v4.py`

```
--reseed N   每个 prompt 抽 N 个 seed，modifier 固定不变。默认 1。
             总张数 = subjects × rounds × reseed
```

两条路径，默认路径必须与历史逐位一致：

| reseed | 行为 |
|---|---|
| 1（默认） | 走原路径：`seed = rng.randrange(...)`，key 为 `{tag}:{index:04d}`。**与改动前逐位兼容** |
| N>1 | prompt 每个 (tag, index) 只组装一次并复用；seed 取自独立随机源 `Random(f"{tag}:{i}:{base}:r{r}")`；key 加 `:r{N}` 后缀，不与普通批次冲突 |

**顺带暴露的原有脆弱性**：任何 modifier 维度的增删都会洗掉全部 seed，因为 `Random.choice()` 每次调用消耗的随机状态数取决于候选个数。实测对比 v4.0 → v4.1（新增 optics + 改为纯 1:1）：

| tag | v4.0 seed | v4.1 seed | 原因 |
|---|---|---|---|
| Nature:0000 | 4171998325 | 4010062671 | 新增 optics 抽取 |
| Ocean:0001 | 708590383 | 432547431 | 新增 optics 抽取 |
| Landscapes:0000 | 2951195675 | 1784145541 | 新增 optics 抽取 |
| Cities:0000 | 678234534 | 678234534 | 偶发巧合：rng 总消耗次数恰好相同 |

不是回归，但说明耦合设计本身不稳。`--reseed` 用独立随机源后，modifier 怎么改都不动 seed。

**验证**（全 21 tag，`reseed=4`，9120 job）

```
distinct keys        9120 / 9120   无冲突
distinct prompts     2280          每个 prompt 用 4 次
distinct seeds       9120 / 9120   无重复
distinct filenames   9120 / 9120   relocate 用 seed 命名，天然不覆盖
anchor_count 1 vs 2  seed 不变 560/560   prompt 变了，seed 一个没动
```

**附带收益**：相同 prompt 连续生成会让 ComfyUI 命中 conditioning 缓存。此前实测同 prompt 12.2s vs 异 prompt 16.2s，所以 `--reseed` 批次的实际速度通常优于 `--sec-per-image` 的估算值。

**建议用法**：先诊断再放量。

```bash

  --tags Landscapes,Nature,Cities --per-tag 8 --reseed 4 --out C:/Home/Temp/JigsawDiag

# 判读：同一 :r0~:r3 组
#   4 张全差 -> prompt（subject / anchor）的问题，改库
#   好坏参半 -> prompt 没问题，靠量筛，加大 --rounds
```
