# docs/archive — 归档文档区

本目录存放**已实施完毕**或**已失效**的设计/计划文档。它们不再描述系统现状，仅作为决策历史保留。

## 为什么要归档

`docs/` 下 90+ 篇文档中，带日期的"设计 / 计划 / 实施报告"占比很高。这类文档在实施完成后会自然失去时效性，但若与现行设计混放同目录，后来者无法区分"这是现状"还是"这是历史"，容易被误导——例如架构主文档曾长期保留已下线的"活动(Events) Tab"与"内置 100 关"描述。

## 归档判定

| 情形 | 处理 |
|---|---|
| 方案已落地实施 | 移入本目录，在文件头加"已实施"标记 |
| 方案前提已失效（如被后续重构推翻） | 移入本目录，在文件头加"已废弃"并注明原因 |
| 现行架构 / 规范 / 指南 | 保留在 `docs/` 根目录 |

## 文档状态标记约定

`docs/` 根目录下的文档建议在标题下方标注状态，便于快速识别：

```
> 状态：现行 / 已实施 / 已废弃
> 最后核对：YYYY-MM-DD
```

未标注状态的文档，默认视为"未定"，读取时需自行回代码核对。
