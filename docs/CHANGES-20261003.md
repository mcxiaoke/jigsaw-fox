### 结论摘要

- 阻塞级 0；高 1；中 6；低 11。
- **核心引擎的数学与拓扑正确**：实测真实散落逐块放置 5×5→24×24 全程集群网格不变量
  无违规，单次 `resolveSnap` 最长 4.9ms；桌面散落约束分配全档位 1 轮命中零冲突、≤4ms。
  这些是本次审查明确"没有发现"的部分。

### 需要关注的缺陷

- **G-1（高）** 进度 / 锁定 / 通关使用三套不同的"就位"判据且互相矛盾：
  `PieceState.isSolved` 的容差与缩放无关（≤0.035），锁定与吸附用随缩放收缩的
  `effectiveSnapDistance()`。实测 1400px 棋盘 zoom=2 时 5×5 的 snap=0.0171 而
  solvedEps=0.035，比值 0.49 —— 存在"进度已 +1 但不吸附、不锁定"的死区。
  `puzzle_state.dart` 中"通关容差 <= 吸附容差"的注释保证在生产链路上不成立。
- **G-2（中）** 桌面散落模式按"扫把整理"时，`_pullbackOutOfBoundsClustersAndPieces`
  用动画启动前的位置计算 shift，其 `animateTo` 会移除前一个 `MoveToEffect`
  （`puzzle_piece_component.dart:487`），导致刚分配的干净槽位被旧位置+shift 覆盖。
  `missingPieceCheck` 已正确调用 `clearMoveEffects()`，说明这是遗漏。
- **G-3（中）** 权威状态从 Flame 组件的瞬时位置反算（`handlePieceDragEnd`、
  `exportSnapshotJson`、`_pullback*`、`_syncResizeTransform`），未与在途补间动画同步，
  可破坏"集群内精确网格相对偏移"不变量（debug 下会抛 FlutterError 红屏）。
- **G-4（中）** `PuzzleEngine._mergeAllAdjacentClusters` 是 `while(changed)` 包裹的
  O(n²) 双循环且每次合并后重启。实测 400 片集群落位 30ms；构造场景（576 片同时网格对齐）
  达 849ms，但该场景正常玩法不可达，属复杂度悬崖而非已确认卡顿。
- **G-5~G-10（低）** "在托盘区域"两套阈值不一致；旋转难度整条链路是死代码且打开即导致
  无法通关；undo/redo/resetCurrentGame 无 UI 入口但持续缓存 30 份完整棋盘状态；
  `hideBorders` 永不置 true；吸附统计被集群规模放大导致成就提前达成；
  `_maxZoom` 实测 2.0~3.285，与"恒为 2.0"的注释不符。
- **D-1（存档，中）** `.bak` 只在单次 `save` 内回滚，成功后立即删除；
  `load` 读到 `FormatException`（含版本过低、`pieces.length != rows*cols`）直接删文件，
  全仓无 `.bak` 提升分支 —— 存档损坏不可恢复。
- **D-2（中）** `ProgressStore.recordDifficultyCompletion` 在落盘失败回滚内存后，
  仍返回 `playCount + 1`，导致磁盘故障期间可反复按"首次通关"领全额奖励。
- **D-3（中）** `EconomyService.consumeHint` 读-改-写非原子，且提示按钮无重入保护，
  双击提示只扣一次费但执行两次 `hint()`。
- **D-4~D-7（低）** `daily_solved` 无按图去重；`default_level` 孤儿快照键仍可写出；
  `reconcileSnapshots` 只挂在 `resetAllData`；`fetchResume` 对 percent>=100 返回 null
  但不清文件与索引。
