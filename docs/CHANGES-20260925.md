# CHANGES 2026-09-25

## 2026-09-25 17:46 取消"按视口翻转拼图模式"机制：模式只由设置决定 + 桌面端最小窗口尺寸

- **问题修复（`lib/game/jigsaw_puzzle_game.dart`）**：
  - `isTabletop` 原先为 `scatterMode == 'tabletop' && (size.x > 450 || size.y > 450)`，会在窗口缩放中途翻转模式，产生两个难以自洽的状态迁移：降级到托盘模式时托盘哨兵碎片（`ny >= 2.0`）失去托盘容器而永久搁浅（原 BUG-4）；反向翻转时散落在桌面四周的碎片被逐片 clamp 到小棋盘上、托盘却为空（原 V10 待确认项）。现改为**纯粹的设置项** `scatterMode == 'tabletop'`；
  - 删除为翻转配套的 `_lastIsTabletop` 边沿检测、`_collectStrandedTrayPieceIds()`、`_rescueStrandedTrayPieces()`，并把 `_syncResizeTransform` 步骤 6 恢复原判据（`isInTray` 早退、clamp 不再改写 `inTray`）——模式固定后"桌面模式下存在托盘语义碎片"已不可达；
  - 附带收益：快照 `extra['scatterMode']` 恒等于设置值，`_applyBoardState` 的 `needsRealign` 只在玩家真的改了设置时触发。
- **小窗口兜底（`lib/main.dart`、`pubspec.yaml`）**：新增依赖 `window_manager: ^0.5.2`，桌面端（Windows/macOS/Linux）在 `main()` 中设置最小窗口尺寸 `kDesktopMinWindowSize = Size(800, 600)`（设置失败仅告警不阻塞启动）；移动端全屏不适用，web 目标本就无法编译（全仓 35 处 `dart:io`），故直接 import 无额外风险。Windows 插件注册文件由构建自动生成。
- **测试补充（`test/game_layout_test.dart`）**：新增 `模式仅由设置决定：tabletop 模式下窗口缩小到极小也不发生模式翻转（V10 回归）`——断言 1280x800 → 400x400 → 1280x800 全程 `isTabletop` 保持 true、全场无 `isInTray` 碎片、无网格不变量违约；托盘模式同理。
- **文档**：实施方案新增 `§〇.1 v3 修订`（记录决策、依据与 V7/V8/V10 作废）；实施总结同步更新至 v3。
- **验证**：`dart format`（仅改动文件）；`flutter analyze` 0 issue；全量 **391 个测试全部通过**；`flutter build windows --debug` 编译成功；`integration_test/app_test.dart -d windows` 集成测试通过。

## 2026-09-25 17:32 修复拼图核心触摸手势 4 处缺陷（托盘滚轮双路径、持片缩放撕裂、残局防丢撕裂集群、桌面模式翻转搁浅）

- **方案文档**：先按二审复核结论修订实施方案（新增 `§〇 v2 修订` V1~V10 清单与退化策略），原稿备份于 `temp/backups/puzzle-core-touch-review-synthesis-and-fix-plan-20260925.md.bak-before-v2-revision`；实施细节见 `docs/puzzle-core-touch-fix-implementation-20260925.md`。
- **BUG-2 托盘滚轮双路径重复 + 坐标错位（`lib/game/jigsaw_puzzle_game.dart`、`lib/pages/game_page.dart`）**：
  - 移除 `JigsawPuzzleGame` 的 `ScrollDetector` mixin 与 `onScroll`：同一次滚轮事件会广播到命中路径上的所有 Listener，游戏侧与页面侧各滚一次（托盘主体实际速度 1.6 倍）；且游戏侧用的是整屏坐标 `eventPosition.global`，与画布相差一个 AppBar 高度，导致托盘命中区整体上移（托盘上方约 58px 区域"边滚托盘边缩放棋盘"）；
  - `GamePage._onPointerSignal` 补齐托盘命中上界（与托盘矩形严格一致）、轴优先序改为取 `|dx|`/`|dy|` 较大者、阻尼 `0.8 → 1.6`（与修复前托盘主体实际速度等价，避免手感回退）。
- **BUG-3 持有碎片期间缩放/改窗口导致集群撕裂（`lib/game/jigsaw_puzzle_game.dart`）**：
  - `_updateBoardTransform`、`_syncResizeTransform`（步骤 5、步骤 6 收拢过滤）统一跳过整个 holding 集群（原先只跳过主片，附属片被重置回拖拽前坐标）；
  - 新增 `_refreshHoldingClusterLayout()`：缩放/尺寸变化后按新 `_zoom` 重排手持集群；光标由"主片位置 + 归一化锚点"反推（不用缓存光标，避免误触发托盘脱离分支），调用点位于 `zoomAt` 末尾与 resize 步骤 5 之后（此时碎片 shape/尺寸已刷新）。
- **BUG-1 残局防丢自检撕裂集群（`lib/game/jigsaw_puzzle_game.dart`、`lib/game/puzzle_piece_component.dart`）**：
  - `missingPieceCheck` 重构为**按集群原子平移**：按 `clusterId` 聚合且每簇只处理一次、跳过含已就位（`isSolved`/`isLocked`）成员的簇、位移取越界最严重成员所需的完整可见目标、整簇统一平移并同步整簇 `nx/ny`，维持"集群内精确网格相对偏移"不变量（旧实现逐片 clamp 会单独撬动成员，撕裂后可把已植入碎片拖离槽位）；
  - 新增 `PuzzlePieceComponent.clearMoveEffects()`：只清 `MoveEffect`（保留 `ScaleEffect`），避免在途动画把整簇拽回失效目标。
- **BUG-4 桌面模式翻转导致托盘碎片搁浅（`lib/game/jigsaw_puzzle_game.dart`）**：
  - `_lastIsTabletop` 在 `onLoad` 初始化，`onGameResize` 检测**模式翻转边沿**（仅 `tray → tabletop` 方向），先收集"仍带托盘语义"碎片（`isInTray` 或状态 `ny >= 2.0` 哨兵），resize 后调用 `_rescueStrandedTrayPieces` 静默转为桌面散落（复用 `_getTabletopScatterSlots` + `_buildScatterAssignment`，同时清 `isInTray`、重写 `nx/ny`），不清洗玩家已摆好的其他碎片；
  - `_syncResizeTransform` 步骤 6：桌面模式取消 `isInTray` 早退保护，两处 clamp 分支同步清除 `inTray` 标志（避免留下托盘优先级 10、被 pullback 永久跳过的残留语义）。
- **RISK-3 集群网格偏移不变量防护**：新增可开关字段 `assertClusterGridInvariant`、校验器 `clusterGridInvariantViolation()` 与 `_debugAssertClusterGridInvariant(tag)`（只校验 `_boardState`，跳过托盘碎片与单成员簇），接入吸附结算、拖拽结束、窗口尺寸同步、防丢自检 4 个出口；release 零开销。
- **RISK-2 注释口径修正**：`effectiveSnapDistance` 注释改为"归一化空间各向同性；映射回屏幕后长边实际半径 = 48 × 长边/短边（非正方形棋盘 > 48px，即屏幕椭圆）"，删除不严谨的"屏幕像素吸附半径恒定"表述。
- **测试补充（`test/game_layout_test.dart`）**：新增"残局防丢自检按整簇原子平移：多片集群推至屏幕外绝不撕裂（BUG-1 回归）"与"单击抓取集群期间滚轮缩放：整簇 scale 与相对偏移同步，不撕裂（BUG-3 回归）"。
- **验证**：`dart format`（仅改动文件）；`flutter analyze` 0 issue；全量 390 个测试全部通过；`flutter build windows --debug` 编译成功。
- **待确认项**：反方向 `tabletop → tray` 翻转时，桌面散落碎片会被逐片 clamp 回棋盘（而非收进托盘），观感为"碎片瞬移、托盘清空"；本次仅保证不搁浅不丢片，是否优化留待需求方确认（详见实施总结第 5 节）。
