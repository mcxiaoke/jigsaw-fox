# 变更记录 2026-08-28

## [2026-08-28 10:15 GMT+8] 新增拼图内容打包工具设计方案

**新增**：`docs/puzzle-content-packaging-tool-design.md` v1.0

**背景**：`puzzle-content-storage-and-expansion-design.md v3` 已落地（`lib/logic/content/`），但 `X:\www\game\test` 测试数据仍由 `scripts/setup_test_server.py` 随机 `tags` 生成，无生产链路；`jigsaw-image-tagging-specification.md` 定义了 25 Tag 单主标签体系但未与打包流程衔接。

**方案要点**：
- 定位：按需启动的本地 `Python http.server + 单页 HTML` 工具（`python scripts/content_studio.py`），平时不常驻，AI 离线打标与本工具解耦（AI 只产出目录级 `tags.json`，本工具做可视化校正与导出）。
- 中间件契约：`tags.json {version, generatedAt, images:[{file, tag, confidence, subject, scene, reason, reviewRequired, correctedTag}]}`，`confidence<0.75` 或 `Others` 自动待复核，校正后以 `correctedTag` 为准映射为 `main.json tags:["Pets"]` 单元素数组兼容现有 `filterByTag`。
- 导出：`main.json:§4.1` / `events.json:§4.3`（zip/array 双模式）/ `daily/YYYYMM.zip`（零元数据，正则校验）/ 可选 `manifest.json` bump；输出到本机 `out/` 再手动复制到 `X:\www\game\test`，后期切 `GitHub manifest + Release`。
- 交互：虚拟滚动缩略图网格 + 25 Tag 单选 + 批量/筛选（待复核/Others 告警）+ 拖拽定 `order` + `localStorage` 记忆。
- 接口：`GET /api/scan|thumb|tags` + `POST /api/tags|export/main|events|daily` 极简 7 接口，前端亦支持纯离线下载降级。

**不改动**：`lib/logic/content/` 管线保持只读消费，符合现有 `CanonicalId` 推导与 `MainContentPipeline` 解析。
