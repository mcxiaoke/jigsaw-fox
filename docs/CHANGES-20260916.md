## 2026-09-16 15:40 修复 verify --remote 大文件下载卡死（urllib 直连加固）

- **现象**：`release_app.py verify --remote` 卡死在首个 APK 流式下载，wget/curl/PowerShell 直连均正常（3~6s 下载完成）。
- **根因**：脚本用 `urllib.request.urlopen` 下载，它会自动读取 **环境变量代理 + Windows 注册表系统代理**（`getproxies()`）；而 wget/curl 只认环境变量。本机残留失效代理（VPN/加速器代理黑洞：TCP 建连但不转发数据）时，urllib 大文件流式下载会无限挂起，HEAD/小 JSON 请求却能通过，故 publish Step 2/3 正常、Step 4 首个大文件即卡死。
- **修复**：`scripts/publish/release_app.py` 新增 `_build_http_opener()`（`ProxyHandler({})` 显式直连），`fetch_remote_stream_and_verify` / `check_remote_head` / `fetch_remote_updates_json` 三处网络调用全部改用该直连 opener。巡检目标均为公网 CDN/镜像，显式直连最可靠。
- **验证**：语法检查通过；冒烟测试（直连拉取 updates.json + HEAD 校验 APK + 流式下载校验 zip SHA256）全部通过；新增 `temp/check_proxy.py` 供卡死环境自查代理来源。

## 2026-09-16 14:40 修复分 ABI 发布 versionCode 偏移导致的 prepare 校验失败与客户端断更隐患

- **根因**：Flutter Gradle 插件在 `--split-per-abi` 构建时会按 `abiIndex*1000 + 基础versionCode` 强制改写各 ABI 包 versionCode（arm64-v8a=2×1000+2=2002），此行为是为 Play Store 多包同时上传设计（见 flutter_tools `FlutterPlugin.kt`）。
- **影响**：发布脚本 `release_app.py` 按设计文档约定的单一 versionCode 模型校验所有包（== 2）必然失败；且即便放开校验，客户端 `update_service.dart` 版本比对 `manifest.versionCode <= 本机versionCode` 会因 2002 恒大于 2 而**永远判定无更新**。
- **修复**：`android/app/build.gradle` 在 `applicationVariants.all` 中强制 `output.versionCodeOverride = flutterVersionCode.toInteger()`，使 all 与各分 ABI 包 versionCode 统一为 pubspec 基础值（自建 R2 + 镜像分发，无需 Play Store 多包同传，故不受影响）。脚本与客户端逻辑无需改动。
- **验证**：`python scripts/release.py --platform android` 重新构建后，aapt 实测 4 个 APK versionCode 均为 2；`python scripts/publish/release_app.py prepare` 全 ABI 校验通过并生成 updates.json。
