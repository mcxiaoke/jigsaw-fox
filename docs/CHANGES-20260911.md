# JigsawFox Changes - 2026-09-11

## 11:00

### Refactor: 全关卡图片存储路径统一收拢至 {appSupport}/levels/ 体系

- **背景**: 关卡图片此前分散在 documents 目录、appSupport 根目录及各自独立文件夹中（如 `network_levels/`、`custom_puzzles/` 等），导致路径割裂且占用用户文档目录。
- **改动**:
  1. `content_manager.dart`: 将 `daily`、`events`、`collections`、`packs` 全部收归到 `p.join(appSupportDir, 'levels', ...)` 统一命名空间下，移除无用的 `appDocumentsDir` 参数。
  2. `level_image_resolver.dart`: 移除对 `getApplicationDocumentsDirectory()` 的错误调用，改为使用 `getApplicationSupportDirectory()`，统一落盘至 `{appSupport}/levels/network/`。
  3. `app_content.dart`: 移除多余的 `getApplicationDocumentsDirectory()` 调用。
  4. `crop_puzzle_page.dart`: 用户自制 UGC 拼图关卡统一输出至 `{appSupport}/levels/custom/`。
  5. `lazy_level_image.dart`: 同步更新类注释与路径说明。
  6. `test/logic/content_manager_test.dart` & `test/widgets/card_new_and_order_test.dart`: 对齐单测沙盒路径至 `supportDir/levels/...`，清理无用参数。
  7. `docs/app-storage-directory-architecture-20260911.md`: 新增应用完整存储与目录结构架构规范文档。
- **效果**: 全模块关卡资源物理路径实现规范化分类隔离，所有 316 项单元与 Widget 测试全量通过。

## 10:14

### BugFix: 首页 main 数据 tag 过滤后图片内容错误 (hash 残留问题)

- **问题**: syncWithRemote 全新关卡分支复用旧本地同名图片文件，不校验 hash。服务端 batch_002 图片更新后，客户端保留了旧版图片（18张：main:101~118），导致 tag 过滤后图片内容不匹配（如美食 tag 出现熊猫/鹦鹉）。
- **根因**: `main_content_pipeline.dart` 在全新关卡时仅检查 `localFile.exists()`，未校验文件 hash 是否与服务端一致。
- **修复**:
  1. `pubspec.yaml` 添加 `crypto: ^3.0.6` 依赖
  2. `main_content_pipeline.dart`:
     - `syncWithRemote` 全新关卡分支：本地存在同名旧图时，先 `fileSizeBytes` 快速筛查，不匹配则直接删除；若 `fileSizeBytes` 匹配（或无此字段），再走 sha256 严格校验。
     - `ensureLevelImageDownloaded` 懒下载：命中本地文件时同样先走 `fileSizeBytes` 比对，不匹配则删除旧图并重下载；无 `fileSizeBytes` 时保留原有行为。
     - 新增 `_sha256File` 辅助方法。
  3. `puzzle_level_item.dart`: 新增 `fileSizeBytes` 字段，兼容旧数据（null 安全）。`fromJson`/`toJson`/`copyWith` 均已支持。
- **效果**: 服务端后续修图/替换批次时，App 会自动清理旧图并重下载，防止图片残留错位。优先用 `fileSizeBytes`（毫秒级）做快速不匹配筛查，sha256 兜底，两者组合兼顾性能与可靠性。
- **校验**: `flutter test` 316 tests all passed; `flutter build windows --debug` 编译通过。
