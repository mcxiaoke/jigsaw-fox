## 0. 一句话原理

拼图的难度来自**局部唯一性**：玩家拿起一块碎片时，要靠这一小块里的信息判断它在全图的哪个位置。

因此选图只看两件事：

1. **像素够不够切** —— 分辨率决定单块碎片能吃到多少像素（硬门槛，可算）
2. **信息够不够认** —— 每一格里有没有可辨识、且不重复的内容（软门槛，可量化）

凡是让某一格变成"放哪儿都对"或"放哪儿都不对"的图，都不是好拼图图。

## 1. 速查卡（打印出来贴墙上）

| 维度 | 及格线 | 推荐值 | 一票否决 |
|------|--------|--------|----------|
| 短边像素 | ≥ 1080 | 1440 ~ 2160 | < 750 |
| 长边像素 | ≤ 3000 | 1920 ~ 2560 | > 4000（会被降采样，白下载） |
| 长宽比 | 接近 1:1 / 2:3 / 3:2 / 3:4 / 4:3 | 恰好是五者之一 | 极端全景（>2.5:1） |

| 格式 | JPG / WebP / PNG | JPG q≥90 / PNG | 带水印、带边框、GIF |

## 2. 硬指标 A：分辨率

### 2.1 计算公式

```
单块碎片像素 = 图片短边像素 ÷ 该方向的最大行列数
```

本游戏五条宽高比的标准档位与最高档（`lib/logic/puzzle_model.dart`）：

| 宽高比 | 常规最高档 (L6) | 宗师最高档 (L7) | 短边方向最大行列数 |
|--------|----------------|----------------|-------------------|
| 1:1 正方形 | 20 × 20 = 400 块 | 24 × 24 = 576 块 | 24 |
| 2:3 竖屏 | 16 × 24 = 384 块 | 20 × 30 = 600 块 | 20 |
| 3:2 横屏 | 24 × 16 = 384 块 | 30 × 20 = 600 块 | 20 |
| 3:4 竖屏 | 18 × 24 = 432 块 | 21 × 28 = 588 块 | 21 |
| 4:3 横屏 | 24 × 18 = 432 块 | 28 × 21 = 588 块 | 21 |

### 2.2 单块像素分级

| 单块像素 | 手感 | 结论 |
|----------|------|------|
| < 30 px | 糊成色块，只能靠形状硬碰 | 不可接受 |
| 30 ~ 45 px | 能看清大轮廓，细节丢失 | 仅够入门档（≤ 64 块） |
| 45 ~ 70 px | 纹理清晰可辨 | 够用（≤ 150 块） |
| 70 ~ 110 px | 细节丰富，放大也不虚 | 优秀（可上 225 ~ 400 块） |
| > 110 px | 过剩 | 浪费流量与显存 |

### 2.3 短边分辨率 → 可支撑的最大档位

| 短边 | 25 块档 | 100 块档 | 400 块档 | 判定 |
|------|---------|----------|----------|------|
| 750 px | 150 px | 75 px | 38 px | **底线**。只能保证全档位"能拼"，大师档画质差 |
| 1080 px | 216 px | 108 px | 54 px | **及格**。全档位可用，推荐入门图包 |
| 1440 px | 288 px | 144 px | 72 px | **推荐**。性价比甜点 |
| 1920 px | 384 px | 192 px | 96 px | **优质**。主力图包标准 |
| 2160 px | 432 px | 216 px | 108 px | **上限**。再大无收益 |

### 2.4 为什么有上限

- 短边 > 2160 px 时，导入管线会等比降采样（显存压制在 15~25 MB），**多下的像素会被丢掉**
- 文件体积：1920×1920 JPG q90 约 500 KB ~ 1.2 MB；4000×3000 可达 4~8 MB，包体与下载耗时都翻倍
- 结论：**下载时就把短边卡在 1080 ~ 2160 区间**，不要贪大

### 2.5 宽高比

游戏按**最小面积损失**原则自动归入 1:1 / 2:3 / 3:2（`PuzzleAspectRatio.fromSize`）。裁切损失公式：

```
CropLoss(r, target) = 1 - min(r / target, target / r)
```

| 原图比例 | 归入 | 裁切损失 | 建议 |
|----------|------|----------|------|
| 4:3 (1.333) | 3:2 (1.5) | 11% | 可接受，但主体要居中 |
| 16:9 (1.778) | 3:2 (1.5) | 15% | 偏大，构图会被切掉两边 |
| 9:16 (0.5625) | 2:3 (0.667) | 16% | 手机竖拍常见，注意主体别在边缘 |
| 1:1 | 1:1 | 0% | 最优 |
| 2.5:1 全景 | 3:2 | 40% | 直接放弃 |

**实操**：搜索时直接用图库的 `orientation` 过滤（横向 / 纵向 / 方形），横向图优先选 3:2，纵向优先 2:3。

## 3. 硬指标 B：可拼性（内容质量）

以下 5 项与 `scripts/puzzle_quality_analyzer.py` 的检测项一一对应，人工筛选时按同样的口径判断，机检只是复核。

### 3.1 死区（Dead Zone）— 第一位杀手

**定义**：切片后该格里几乎全是纯色或平滑渐变，没有任何可辨识的图案或边缘。

**典型死区源**：天空、水面、纯色墙、虚化背景（bokeh）、雪地、沙滩、夜空、纯色卡纸背景、大面积皮肤。

**人工判断法（网格预演）**：在图上比划目标档位的网格（如 10×10），逐格问"这一格里有什么可认的东西"。答不上来就是死区。

**分级**：

| 核心区死区占比 | 判定 | 处置 |
|----------------|------|------|
| ≤ 3% | S 级 | 直接收录，可上大师档 |
| 3% ~ 8% | A 级 | 收录，100 块以内 |
| 8% ~ 15% | B 级 | 需裁切，或限入门档 |
| 15% ~ 22% | C 级 | 先裁切再复检 |
| ≥ 22% | F 级 | 淘汰 |

**边缘死区宽容度更高**：四周边框格玩家靠"直边"就能定位，脚本对边框死区的惩罚只有核心区的 1/4。所以**顶部一条天空可以忍，画面正中间一片纯色不能忍**。

### 3.2 清晰度（Laplacian 方差）

反映全图边缘能量，值越高纹理越锐利。

| 值 | 判定 |
|----|------|
| ≥ 600 | 锐利，适合 225+ 块宗师档 |
| 300 ~ 600 | 清晰，适合 100 ~ 144 块 |
| 50 ~ 300 | 偏软，适合 ≤ 64 块 |
| 25 ~ 50 | 明显虚化，不推荐 |
| < 25 | 淘汰 |

**人工判断**：把图 100% 放大看细节，发丝、叶脉、砖缝是否还成立。柔焦小清新、重虚化人像、AI 生成图的涂抹感都会压低这个值。

### 3.3 色彩多样性（色相熵 + 饱和度分散度）

单色系照片（全蓝的海、全绿的林、全灰的雾）即便纹理够，也会让相邻碎片难以区分。

- 色相熵目标 **≥ 2.6**（满分 4.0），优秀 **≥ 3.2**
- 画面里至少有 **3 个可区分的色块区域**（如暖色主体 + 冷色背景 + 点缀色）
- 避免：黑白照片（除非明暗层次极强）、单色调滤镜、雾景、逆光剪影

### 3.4 空间分布均衡

**问题图**：一个小主体杵在正中间，四周全是空背景。结果是中间 20% 的格子信息过载，外围 80% 全是死区。

- 目标：**spatial_balance ≥ 60**，推荐 ≥ 80
- 人工判断：主体应占据画面 **40% ~ 70%**，且画面四角、四边均有内容（哪怕只是质感变化）
- 好例子：满构图的花田、街景、密林、市集
- 坏例子：一只鸟站在大片空白处、极简产品图、留白设计的海报

### 3.5 重复纹理歧义（脚本目前未覆盖，需人眼把关）★

**这是死区的反面，但同样致命**：死区是"没有信息"，重复纹理是"信息有歧义"——一块碎片放哪儿看起来都对，玩家只能反复试错，体验比死区还差。

| 高危图案 | 说明 |
|----------|------|
| 等距条纹（斑马纹、百叶窗、木纹地板、条纹衬衫） | 一格内容在垂直方向有 N 个等价位置 |
| 规则阵列（瓷砖墙、蜂巢、书架、窗户阵列、停车场） | 网格状重复，网格还容易和切片网格共振 |
| 同心圆 / 放射状（水波纹、螺旋楼梯、向日葵花盘） | 旋转对称造成位置歧义 |
| 大面积纯噪点（沙地、砾石、星空） | 每格纹统计上一致，属于"高熵死区" |
| 观叶植物 / 龟背竹 / 整片枫叶 | 叶片形状高度相似 |

**判断法**：用手指遮住图的一个区域，问自己"这块内容在图上还有几个几乎一样的地方"。≥ 3 处就降级处理。

> **待办**：后续可在 `puzzle_quality_analyzer.py` 增加自相关（autocorrelation）周期检测项，用 FFT 主频能量占比量化重复度，阈值建议 > 0.35 判为高重复。

## 4. 硬指标 C：构图与题材

### 4.1 推荐题材（红榜）

| 题材 | 为什么适合 | 备注 |
|------|-----------|------|
| 层次丰富的风光 | 前景/中景/远景三段式，天然分区 | 云层要有形状，避免纯蓝天空占 1/3 以上 |
| 城市街景 / 建筑群 | 线条、窗户、招牌提供大量锚点 | 现代玻璃幕墙易成死区，选老城区更佳 |
| 花卉植物（特写/密植） | 色彩层次好、纹理细密 | 避开单朵大花的留白构图 |
| 动物（带环境） | 毛发纹理 + 环境色区分 | 避开纯色背景棚拍 |
| 美食 / 市集 / 复古海报 | 元素杂、色彩多、分布散 | 天然高空间均衡 |
| 细节密集型插画 | 信息密度高、无死区 | 避开扁平极简风插画 |
| 机械 / 钟表 / 蒸汽朋克 | 结构线极丰富 | 小众但拼感极佳 |

### 4.2 劝退题材（黑榜）

| 题材 | 问题 |
|------|------|
| 极简 / 留白设计图 | 90% 面积是死区 |
| 纯渐变背景 / 抽象色块 | 无锚点，全图歧义 |
| 夜景大片暗部 / 剪影 | 暗部既是死区又缺色彩 |
| 雪景 / 雾景 / 沙漠 | 低对比 + 单色 + 纹理重复 |
| 大面积水面 / 纯净天空 | 经典死区源 |
| 人脸特写 / 棚拍模特 | 大面积肤色死区 + 虚化背景 |
| 含大量文字的图（海报、截图、封面） | 文字被切开后失去语义，且笔画是高频重复纹理 |
| 条纹 / 格子 / 瓷砖类图案 | 见 §3.5 重复歧义 |
| AI 生成图（未精修） | 常有局部涂抹、结构崩坏、细节不一致，会制造"假锚点" |
| 漫画分镜 / 多格拼接图 | 黑边框会与切片网格共振，且分格间是硬边界 |

### 4.3 文字的特殊处理

- **可接受**：招牌、路牌、书名等作为画面元素少量出现
- **不可接受**：文字占画面 > 15%，或文字是画面主体（海报、壁纸、PPT 截图）
- 原因：文字被切碎后玩家无法利用语义，只剩笔画的无规律高频噪声

## 5. 一票否决清单（任一命中即淘汰）

1. 短边 < 750 px
2. 含水印、LOGO、二维码、站名角标
3. 自带边框、圆角、留白卡纸边、拍立得相框
4. 核心死区 ≥ 22%
5. Laplacian 方差 < 25
6. 明显过曝（大片死白）或欠曝（大片死黑），暗部/亮部占比 > 30%
7. 强周期性重复纹理（条纹 / 阵列 / 同心圆）覆盖 > 25% 画面
8. 多图拼接、拼贴画、带 UI 元素的界面截图
9. 许可不明、来源不可追溯
10. 含可识别人物肖像但无肖像权授权
11. 含第三方品牌 LOGO、受版权保护的角色/IP 形象
12. 含敏感地图边界表述错误、政治或宗教争议内容

## 6. 人工 30 秒快筛法（没有脚本时）

拿到一张图，按这四步走，30 秒出结论：

**Step 1 · 看尺寸（3 秒）**
右键属性/图库详情页，短边是否在 1080 ~ 2160 之间。不在就换图。

**Step 2 · 缩略图测试（10 秒）**
把图缩到 **200 px 宽**观看（系统预览/浏览器缩放）。这一步模拟玩家看单块碎片的信息量。
- 缩小后**仍能一眼认出这是什么、有几块明显不同的区域** → 通过
- 缩小后变成一团糊、或变成一片单色 → 淘汰

**Step 3 · 网格预演（12 秒）**
在图上比划 10×10 网格，重点扫四个角和正中间：
- 纯色格 ≤ 3 格 → S/A 级
- 纯色格 4~8 格 → 看是否集中在边缘，边缘可忍，核心不行
- 纯色格 > 8 格 → 淘汰或裁切

**Step 4 · 重复扫描（5 秒）**
找有没有出现 3 次以上的相似图案（条纹、窗格、树叶、波浪）。有就降级一档。

## 7. 与现有工具链的对接

### 7.1 下载阶段参数（`batch_image_downloader.py`）

```
min_width      = 1080      # 硬过滤，低于此值不下载
orientation    = 按分类指定：landscape→3:2 素材 / portrait→2:3 素材 / square→1:1 素材
per_page       = 200
sources        = pixabay / pexels / unsplash / openverse
```

### 7.2 机检复核（`puzzle_quality_analyzer.py`）

人工筛过之后再跑机检，重点看这四个字段：

| 字段 | 通过阈值 | 对应本文章节 |
|------|----------|--------------|
| `core_dead_ratio` | ≤ 0.08 | §3.1 |
| `laplacian_var` | ≥ 300 | §3.2 |
| `color_entropy` | ≥ 2.6 | §3.3 |
| `spatial_balance` | ≥ 60 | §3.4 |

等级映射与处置：

| 机检等级 | 分数 | 处置 |
|----------|------|------|
| S | ≥ 80 且核心死区 ≤ 4% | 收录，开放 64 ~ 225+ 块 |
| A | ≥ 68 且核心死区 ≤ 8% | 收录，开放 36 ~ 100 块 |
| B | ≥ 55 且核心死区 ≤ 15% | 先裁切，或限 16 ~ 25 块 |
| C | 其余 | 仅 16 块，需边缘裁切 |
| F | 核心死区 ≥ 22% 或分数 < 45 | 淘汰 |

### 7.3 人工 vs 机器的分工

| 判断项 | 人工 | 机器 |
|--------|:----:|:----:|
| 分辨率与比例 | ✓ | ✓ |
| 死区分布 | ✓ | ✓ |
| 清晰度 | — | ✓ |
| 色彩熵 | — | ✓ |
| **重复纹理歧义** | **✓** | ✗（待补） |
| **题材适宜性** | **✓** | 部分（VLM 阶段） |
| **水印 / 边框 / 文字** | **✓** | ✗ |
| **版权与合规** | **✓** | ✗ |

结论：**机器负责筛掉 70% 的技术不合格图，人负责守住剩下的题材、歧义与合规。**

## 8. 格式与合规

### 8.1 文件格式

| 用途 | 格式 | 参数 |
|------|------|------|
| 照片类 | JPG | quality ≥ 90，无二次压缩 |
| 插画 / 需无损 | PNG | 8-bit RGB，不带 alpha（拼图不需要透明通道） |
| 体积敏感 / 云端分发 | WebP | quality ≥ 85 |
| 缩略图 | WebP | 320 px 短边，quality 80 |

- 色彩空间 sRGB，不带 ICC Profile（Flutter 解码行为一致）
- 剔除 EXIF GPS 与拍摄者信息，保留方向标记或提前烘焙旋转
- 单张成品 ≤ 2 MB（1920 短边 JPG q90 通常在 1 MB 以内）

### 8.2 命名与归档

```
assets/images/levels/<category>/<category>_<4位序号>_<短边>px.<ext>
例：landscape/landscape_0031_1920px.jpg
```

同目录维护 `levels_manifest.json`，每条必须包含：

| 字段 | 说明 |
|------|------|
| `id` | 与文件名一致 |
| `category` | animals / plants / architecture / landscape / anime / featured |
| `source_platform` | pixabay / pexels / unsplash / openverse |
| `source_url` | 原始页面直链，可追溯 |
| `license` | 许可类型，必须与平台一致 |
| `width` / `height` | 实际像素 |
| `max_tier` | 建议开放的最大难度档位 |
| `tags` | 遵循 `docs/jigsaw-image-tagging-specification.md` |

### 8.3 版权红线

- **可用**：CC0 / 公共领域 / Unsplash License / Pexels License / Pixabay Content License / 自购授权 / 自有原创
- **需署名**：CC-BY、CC-BY-SA —— 必须在 App 内"关于-素材来源"页面列出，否则不用
- **禁用**：百度图片、花瓣、千图网、Pinterest 转载等无明确许可来源
- **禁用**：含可识别人物（CC0 不等于肖像权授权）、含品牌 LOGO、含受版权保护的动漫角色

## 9. 验收 Checklist

每张图入库前逐项打勾：

- [ ] 短边 1080 ~ 2160 px，长边 ≤ 3000 px
- [ ] 宽高比接近 1:1 / 2:3 / 3:2，裁切损失 < 15%
- [ ] 缩略图测试通过（200 px 宽仍可辨识结构）
- [ ] 10×10 网格预演，纯色格 ≤ 8 格且不成片
- [ ] 核心区（去掉最外一圈）无大片纯色
- [ ] 无 ≥ 3 次重复的周期性图案
- [ ] 无水印、无边框、无 UI 元素，文字占比 < 15%
- [ ] 无过曝/欠曝，暗部与亮部合计 < 30%

## 10. 常见误区

| 误区 | 纠正 |
|------|------|
| "分辨率越高越好" | 短边 > 2160 会被降采样，等于白下载 |
| "好看的图就是好拼图图" | 极简大片好看但最难拼，拼图要的是"乱而有序" |
| "死区只在天空" | 水面、墙面、皮肤、虚化背景、雪地、暗部都是 |
| "高清图就不会有死区" | 死区是内容属性，与分辨率无关 |
| "纹理越密越好" | 密到变成均匀噪点（沙地、砾石）同样是死区 |
| "AI 生成图省事" | 结构崩坏与重复细节会产生假锚点，慎用 |
| "裁掉天空就万事大吉" | 核心区死区无法通过裁切消除 |
