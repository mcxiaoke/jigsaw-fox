## [2026-08-31 08:20 GMT+8] 批量生成脚本新增长跑稳定性防护（定时硬重置 + 驱动卡死检测）

**修改文件**：`scripts/comfyui_batch_gen.py`、`docs/comfyui-batch-generation-guide.md`

**背景（真实故障）**：`--rounds 18` 连续跑至第 1550 张（约 7 小时）时 CUDA 驱动卡死，整机假死需强制关机。事后检查 `C:/Home/Temp/JigsawOutput/_progress.json`：**done=1550、failed=0，7 个 tag 各 216 张（12 subject × 18 轮）已完整产出，Cities 进行到 44/216** —— 断点续跑机制在真实故障下验证有效，无一张丢失。

**改动内容**：
- **定时硬重置** `--hard-reset-minutes`（默认 10）：每 N 分钟调用 `/free {unload_models: true, free_memory: true}`，主动清空显存碎片与驻留模型，让 GPU 周期性复位，对抗长跑碎片累积导致的驱动挂起。代价可忽略（每次释放后下一张重载 +7s，按 10 分钟 37 张折算约 0.2s/张）；
- **卡死检测** `--stuck-timeout`（默认 90s）：新增 `wait_for_image()` 替代原来的固定轮询 —— 单张超过阈值未出图时用 `/system_stats` 短超时探活，驱动挂起时立即抛 `ComfyStuck` 而非干等 240s；卡死图**不重试**（驱动级挂起重试无意义且有风险）；
- **连续卡死中止** `--max-stuck`（默认 3）：连续 N 张判定卡死后主动落盘进度并退出，避免整机假死时连进度都保不住；
- `ComfyClient` 改造：`_request` 支持单次调用 `timeout` 覆盖，新增 `alive()` 探活方法，新增 `ComfyStuck` 异常类型；
- 文档 §7.5 参数表补齐三个新参数（`--sec-per-image` 默认值同步修正为 16s），新增 **§7.7 长跑稳定性**章节：记录 1550 张卡死的实测教训、三层防护机制、四项降低卡死概率的措施（移除第三方 custom nodes / 不并行吃显存程序 / 中途检查单张耗时 / 调大释放频率），并明确"驱动级硬卡死软件无法自救，脚本只做预防 + 早止损"这一边界。

**防护边界说明**：驱动硬卡死属于 WDDM/TDR 层面，脚本无法自救；能做的是降低发生概率（定时释放、移除泄漏源）与保住进度（探活早停、进度落盘）。真卡死后流程为：重启机器 → 启动 ComfyUI → 重跑同一条命令续跑。

**验证**：`py_compile` 通过；`--rounds 1` dry-run 正常（252 jobs、节点探测 4/8/6/10）。尚未在长跑中实测 hard reset 触发。
