## 1. 定位与问题

### 1.1 产品定位

- 休闲解压：玩家为放松与完成愉悦而来；
- 商业模型 = 卖内容（图集/主题包），收入靠「玩得久 + 玩得满意 + 续买」；
- 推论：**主流程任何环节不得出现负面评价**（「只得 1/2 星」「差 X 秒满星」「缺 X 张三星」等）。

### 1.2 现状问题（代码事实）

| # | 系统 | 现状 | 本期处置 |
| --- | --- | --- | --- |
| S1 | 难度解锁 `unlock_service.dart` L29 `kDifficultyStarImageRequirements` | 解锁高档需「3 星不同图片数 ≥ N」（L57-58） | D2：不改（D1 后三星=≤2 次提示，门槛自然消解） |
| S2 | 金币 `economy_service.dart` L38 `kStarBonusTable` | 奖励按星级阶梯，差星少钱 | D3：脱钩 |

### 1.3 核心认知

星级不是问题，**「星级=考试分数」才是问题**。休闲轨把星级变成「无提示完成的嘉奖」，速度不再考核——移除时间压力是「不焦虑」的关键。

## 2. 方案总览（两轨制）

| 维度 | 休闲轨（默认主流程，本期落地） | 挑战轨（可选，D4 后续） |
| --- | --- | --- |
| 定位 | 放松解压、完成即快乐 | 自愿竞技、自我超越 |
| 结算 | 完成即全星庆祝，无「未满星」 | 后续设计（严格阈值/徽章） |
| 星级 | ≤2 次提示 = 3 星（时间/片数不参与） | 速通/大师等严格目标 |
| 失败反馈 | 不存在失败概念 | 后续定义 |
| 内容/货币 | 星级不锁内容、不定金币 | 后续定义 |

核心原则：**休闲轨 100% 零打击；技术性评价整体留待挑战轨，让追求「纪录」成为主动选择而非日常压力。**

## 3. 设计原则

- **P0 零打击**：常规游玩无负面评价、无缺失感反馈；
- **P1 完成即嘉奖**：星星是庆祝彩带，不是考卷分数；
- **P2 目标 ≠ 评价**：收集/进度做目标，星级做记录；
- **P3 不设墙**：星级不挡内容（本期 D2 天然满足）；
- **P4 辅助无焦虑**：提示 ≤2 次仍 3 星、>10 次才 1 星；看原图/撤消不参与；
- **P5 速度不考核**：星级与时间彻底解耦，UI 时间仅参考。

## 4. 休闲轨设计（本期落地）

### 4.1 结算体验（S3）

- 胜利弹窗：彩带 + **三星依次点亮（保留现动画）**，常规完成即 3 星齐亮；
- 常规路径不展示「只亮 1~2 颗」：后台星级 < 3 时也正常庆祝，不渲染空星/灰星、不写「只得 X 星」；
- **用时弱化**：时间降为次要灰字（中性记录），不与星级/庆祝并排强调；
- 展示主次：完成图 → 收集进度 → 奖励到账 →（次要）用时。

### 4.2 星级判定 —— 提示次数绝对阈值（D1 定稿，S5）

```
hints ≤ 2   → 3 星（几乎不用提示 / 新手试 1~2 次仍是嘉奖）
hints ≤ 10  → 2 星
hints > 10  → 1 星（只有频繁依赖提示才降级）
```

```dart
static int starsFromHints(int hints) {
  if (hints <= 2) return 3;
  if (hints <= 10) return 2;
  return 1;
}
```

说明：
- **与片数、时间完全无关**：规则一句话可讲清，无档位差异、无取整边界、无百分比折算；
- 语义依据：**提示是新手辅助**——会玩高难度的玩家基本不用提示；用绝对阈值（而非片数百分比）对新手最友好：小图用 1~2 次提示依然 3 星；
- 边界必然存在（任何阈值都有界），选 `≤2 / ≤10` 两个直观整数：3 星覆盖「几乎零提示」的荣誉感，1 星只惩罚「>10 次」的极端依赖；
- **时间、看原图、撤消、重试均不参与星级**——焦虑源整体移除；
- 存档语义：星级 ≈ 「提示克制度」的纪念章；常规游玩基本落在 3 星。

### 4.3 难度解锁（D2：不改，S1）

- 维持「3 星不同图数」口径：D1 后三星 = ≤2 次提示完成，对新手的达成门槛极低，解锁不再是压力点；
- 风险注：若后续发现高档（L5+ 大图）完成本身偏慢、解锁偏慢，再单独评估「完成图数」口径（本期不动）。

### 4.4 金币脱钩 + 提示降价 + 每日免费（D3，S2）

**金币与星级脱钩**（推荐：改表语义、数值不动）：
- `kStarBonusTable` 改为**固定完成加成 = 原 3 星档值**：`rewardFor(tier) = Base[tier] + bonus3[tier]`，与星级无关；
- 结算：首次完成 = 全额完成奖励；复玩 = 20% Base 保底；`deltaStars` 破星分支停用（保留兼容）；
- `starCoins` 展示语义改为「完成奖励」。

**提示降价**（建议值，可调）：

| 档位 | L1 | L1.5 | L2 | L3 | L4 | L5 | L6 | L7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 现值 | 5 | 6 | 10 | 15 | 20 | 25 | 35 | 45 |
| 建议 | 2 | 3 | 5 | 7 | 10 | 13 | 18 | 23 |

**每日免费 10 次**（跨档位共享）：
- 新增存储 `econ:dailyFreeHints`（int），复用 `econ:dailyDate`（与金币日上限同键）；
- `consumeHint` 优先级：**今日免费额度（<10）→ 免费券 → 金币 → 失败**；
- 新增 getter `dailyFreeHintsLeft`；提示按钮可显示「今日免费 X/10」；
- 按 `_todayDateStr()` 每日自然重置（与现日上限逻辑一致）。

### 4.5 成就（S4）

- 「三星」类成就（如「三星启航」）语义自动变为「**≤2 次提示通关**」——低门槛自然达成；
- 本期不改成就表结构（减法），仅校正文案与触发语义。

### 4.6 UI 预估时间放宽（总则）

星级已不看时间，预估只作「安排碎片时间」的参考 → 放宽、弱化承诺感：

| 档位 | 现文案 | 建议（宽） |
| --- | --- | --- |
| L1 | 1~3 分钟 | 约 1~5 分钟 |
| L1.5 | 2~4 分钟 | 约 2~8 分钟 |
| L2 | 5~8 分钟 | 约 4~15 分钟 |
| L3 | 12~18 分钟 | 约 8~30 分钟 |
| L4 | 25~35 分钟 | 约 15~45 分钟 |
| L5 | 50~75 分钟 | 约 30~90 分钟 |
| L6 | 1.5~3 小时 | 约 1~3 小时 |
| L7 | 3~5 小时 | 约 2~6 小时 |

实现：`puzzle_model.dart` `estimatedMinutes` 静态文案更新即可（getter 现位于 `lib/logic/puzzle_model.dart:246` 一带）。

### 4.7 计时器保留（只作展示/统计）

- `_seconds`、快照 `elapsedSeconds`、游玩时长成就等保留，但**不再作为评星输入**；
- `_hintPauseUntil`、看原图停表等机制失去评星意义，本期不动代码（减法），仅不再用于星级。

### 4.8 分享卡（D5：本期不动）

保持现状，不渲染星级缺口即可；不做新样式。

## 7. 数值与校准

- 星级只由提示次数决定（≤2 / ≤10 / >10），与时间、片数无关 → 时间基准表不参与评星，仅服务 §4.6 预估文案（后续可埋点校准 P50~P95）；
- 阈值以玩家提示使用分布校准：观察「≤2 次 / 3~10 次 / >10 次」三档占比，若 2 星带过宽可下调 10 → 6 等（运营期可调）；
- 免费 10 次/日与降价表为初值，运营期可调。

## 8. 风险与兼容

- **已得记录**：`bestStars` 保留纯记录，存量星级不回退、不参与门槛；
- **经济**：星级加成拉平 + 提示降价 → 供给/消耗同步下调；首通收益与旧「3 星收益」一致（推荐做法），无骤降体感；日上限 200 不变；
- **成就存量**：已领取三星成就保留；文案口径变更不影响已解锁状态；
- **行为观察**：上线后看「≤2 次提示完成率」（≈三星率）、提示日均用量（免费 10 次是否够）、完成到卸载时长，验证零打击是否达成。
