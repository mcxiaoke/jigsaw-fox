## Studio 导出转码并行化提速（图片级多进程，约 3.4~4.6x）

> 现象：导出 16 张图耗时约 1 分钟且全程无中间日志/进度。定位：单张 libwebp
> `method=6` 编码为耗时主体（6000×4000 大图实测 4~7s/张），换库（vips/NConvert/
> pyvips）单张仅快 20~50%；数量级加速来自「多图并行」——XnConvert 50 张/14s 同为此原理。

### 实测基准（本机 8 核 16 线程，webp q70）

```
16 张大图(共309MB, F: 盘源)         耗时      相对加速
Pillow m6 顺序(原实现)              86.9s      1x
Pillow m6 进程池 x8                 19.0s      4.6x
vips effort=6 进程池 x8             14.2s      6.1x   (vips 编码略快 ~25%，引入外部依赖)
NConvert 单进程                     ~2.9s/张    ~2x
pyvips 顺序(内部线程)               69.2s      1.3x
```

### 方案

`studio/core/image_proc.py` 新增：
- `sha256_file()` — 文件哈希（worker 内自足）
- `_convert_one_parallel(job)` — 模块级进程池 worker（Windows spawn 可 pickle）
- `_default_export_workers()` — worker 数：环境变量 `STUDIO_EXPORT_WORKERS` 优先，否则 `min(8, CPU核数)`
- `convert_images_parallel(tasks)` — 并行批量转码；进程池不可用时自动回退串行，绝不中断导出

三个导出器的图片转码循环改为「父进程备元数据 → 进程池并行转码 → 按序组装」，
产物（文件名/顺序/标签/hash）语义与串行完全一致：
- `studio/exporters/main_exporter.py` — 主线图片转码
- `studio/exporters/pack_exporter_base.py` — event/collection ZIP 内图片转码（临时文件名加 pack_id+idx 防冲突）
- `studio/exporters/daily_exporter.py` — daily ZIP 内图片转码（同上）

- 端到端（隔离临时源目录，12 张混合大图含 3 张 30MB+ PNG）：串行 ~69s → 并行(8) 20.3s，

## 1. 标签规则统一：无标签素材一律落成规范兜底标签 [Others]

> 用户要求「把没有 tag 的当作 Others tag，统一排序规则」。落地为一条**标签不变量**：
> 素材无标签 / 标签无法归类时，`tags` 一律为 `["Others"]`（taxonomy 规范形式，大写 O），
> 绝不出现空数组或小写 `"others"`。于是「是否未分类」在任何位置都等价于 `OTHERS_TAG in tags`，
> 筛选 / 统计 / 待复核判定不再需要分散的特判分支。

### 涉及文件

- `studio/taxonomy.py` — 新增唯一规范常量 `OTHERS_TAG = "Others"`
- `studio/core/tags_manager.py` — **修复潜在 bug**：`("others" in tags)` 对规范形式 `"Others"` 永远为假，导致高 confidence 的未分类素材不会被自动标记待复核；改为 `OTHERS_TAG in tags`（实测：conf=1.0 未打标 → `review_required=True`，修复前为 False）
- `studio/server.py` — 导出预检的兜底标签由小写 `["others"]` 改为 `[OTHERS_TAG]`（实测预览 `stats.tags` 键由 `others` 统一为 `Others`）
- `studio/exporters/main_exporter.py` — 双写兼容分支收窄，改用常量
- `studio/static/js/app.js` — 前端引入标签不变量三件套：
  - `normalizeTags(tags)`：去空去重、小写 others 一律规范为 `"Others"`，空则落 `[OTHERS]`；
  - `isOthers(r)` / `isOthersTag(t)`：统一的「未分类」判定；
  - `applyTags(r, tags)`：写入 tags 时同步 `catalogs` 与 `review_required`，保证不变量恒成立。
  - 入口收口：扫描加载（`doScan`）与导出成功后的重拉均做归一化；`batchSetTag` / `batchAddTag` / `batchRemoveTag` / `batchClearTags` / `toggleViewerTag` 全部改走 `applyTags`。
  - 判定坍缩：`tagCounts` 直接平铺计数（Others 不再单独虚拟累加）、`unreviewedCount` / Others 过滤 / 「选待复核」从「空数组或全 others」的多条件特判统一为 `isOthers(r)`。

### 3.1 主界面输出字段下沉

输出目录 (Output Directory) / HTTP 根地址 (HTTP Base) 不再是主界面配置栏的字段——它们属于"导出确认前才需要决定"的产物输出设置。

- 两者作为「📦 输出设置」卡移入导出流程第③步（导出前预览），以 `*` 标注输出目录为必填；填写即记忆 `localStorage`，改动会重跑预检让「建议起始序号/版本」基于真实产物目录。
- 旧的 `persistConfig` 之前**没有暴露到 return 块**（仅 main bar `@change` 静默失效），本次顺带修正。

### 3.2 空输出目录点导出有明确报错

之前 `runExport` 校验只在 toast 闪一条就 return，导出大屏下一闪即逝，给操作者"没反应"的感觉。
- 新增 `exportError` ref：`runExport` 入口先清空，再分别校验「源目录 / 输出目录 / 标题（event+collection）」，不通过则把具体原因写到 `exportError` 并 toast 提示，`exportStep` 保持 3，不误入导出。
- 第③步 body 顶部加 `<div v-if="exportError" class="export-error-banner">` 红条，**持久展示**直到用户在输出设置或第①步修正（`goExportStep` / `openExport` / `onOutputChange` 都会清空）。
- 文案按"少了什么 → 在哪里补"两句式说清，例如：`输出目录为空：导出前请先在上方填写 输出目录 (Output Directory)。`

### 3.3 一键随机排序（tag 均分）

第②步新增「🎲 随机排序 (tag 均分)」按钮，与「↕ 整体反转」并列。
- 算法：从每张图的 tags 里取首个真实标签（无则归 OTHERS 桶），组内 Fisher-Yates 洗牌；组间按 **taxonomy 顺序**（其他=17 在末位，未知名排在 Other 之前）排序后做**欠账优先贪心**：
  - 每个 tag 的「欠账」= `(pos+1)/N × count − 已出数`，欠得最多的下一格出列（同分按 taxonomy 顺序破平）。
  - 若最优组与上一格相同且存在别的可选组，则改取次优组（避免同 tag 紧邻）。
  - 强制头部为 taxonomy 顺序的第一个非空组，保证序列观感从真实分类起。
- 该算法在常见分布下**理论最优**：同 tag 不会出现连续，除非某组数量大到无解（如某组占 30+、总 40，理论最小邻接 19 也已达成）；数量较均衡时（4×10、5×8 等）邻接为 0。
- 随机后 `sortBy` 自动切到 `manual`，仍可继续手动拖拽 / ↑↓ 调整。
