- **方案**：新增轻量端点 `GET /api/quality/scores?dir=...`，后端一条 SQL JOIN 查询（`file_cache LEFT JOIN quality_cache`）返回 `{path: quality_dict}` + stats，纯 SQLite 不碰文件系统；前端 `finalizeQualityJob` 改为调用 `fetchQualityScores()` merge 到已有 records，不替换整个数组。
- **改动**：

## Studio 导出转码并行化提速（图片级多进程，约 3.4~4.6x）

> 现象：导出 16 张图耗时约 1 分钟且全程无中间日志/进度。定位：单张 libwebp
> `method=6` 编码为耗时主体（6000×4000 大图实测 4~7s/张），换库（vips/NConvert/
> pyvips）单张仅快 20~50%；数量级加速来自「多图并行」——XnConvert 50 张/14s 同为此原理。

### 实测基准（本机 8 核 16 线程，webp q70）

```

Pillow m6 顺序(原实现)              86.9s      1x
Pillow m6 进程池 x8                 19.0s      4.6x
vips effort=6 进程池 x8             14.2s      6.1x   (vips 编码略快 ~25%，引入外部依赖)
NConvert 单进程                     ~2.9s/张    ~2x
pyvips 顺序(内部线程)               69.2s      1.3x
```

### 方案

`studio/core/image_proc.py` 新增：
- `sha256_file()` — 文件哈希（worker 内自足）

- `_default_export_workers()` — worker 数：环境变量 `STUDIO_EXPORT_WORKERS` 优先，否则 `min(8, CPU核数)`
- `convert_images_parallel(tasks)` — 并行批量转码；进程池不可用时自动回退串行，绝不中断导出

三个导出器的图片转码循环改为「父进程备元数据 → 进程池并行转码 → 按序组装」，

- `studio/exporters/main_exporter.py` — 主线图片转码
- `studio/exporters/pack_exporter_base.py` — event/collection ZIP 内图片转码（临时文件名加 pack_id+idx 防冲突）
- `studio/exporters/daily_exporter.py` — daily ZIP 内图片转码（同上）

## 1. 标签规则统一：无标签素材一律落成规范兜底标签 [Others]

> 用户要求「把没有 tag 的当作 Others tag，统一排序规则」。落地为一条**标签不变量**：

### 3.3 一键随机排序（tag 均分）

第②步新增「🎲 随机排序 (tag 均分)」按钮，与「↕ 整体反转」并列。
- 算法：从每张图的 tags 里取首个真实标签（无则归 OTHERS 桶），组内 Fisher-Yates 洗牌；组间按 **taxonomy 顺序**（其他=17 在末位，未知名排在 Other 之前）排序后做**欠账优先贪心**：
  - 每个 tag 的「欠账」= `(pos+1)/N × count − 已出数`，欠得最多的下一格出列（同分按 taxonomy 顺序破平）。
  - 若最优组与上一格相同且存在别的可选组，则改取次优组（避免同 tag 紧邻）。
  - 强制头部为 taxonomy 顺序的第一个非空组，保证序列观感从真实分类起。
- 该算法在常见分布下**理论最优**：同 tag 不会出现连续，除非某组数量大到无解（如某组占 30+、总 40，理论最小邻接 19 也已达成）；数量较均衡时（4×10、5×8 等）邻接为 0。
- 随机后 `sortBy` 自动切到 `manual`，仍可继续手动拖拽 / ↑↓ 调整。
