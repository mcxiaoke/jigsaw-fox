# Content Studio 基于文件内容 Hash 的防重导出与打标自动追踪技术方案

> **版本**：v1.0  
> **日期**：2026-09-05  
> **适用模块**：Content Studio 后端服务 (`studio/server.py`、`studio/core/`、`studio/exporters/`) 与 前端工作台 (`studio/static/`)  

---

## 一、 背景与核心痛点

在以往以“文件相对路径”（如 `Animals/lion_01.jpg`）作为唯一索引的素材管理机制中，存在两大结构性缺陷：

1. **改名或移动导致打标成果丢失（“路径断裂”）**：
   - 运营人员对 `lion_01.jpg` 进行了精细的多标签标注并标记为“已复核”；
   - 后续在本地文件管理器中若将图片重命名为 `african_lion.jpg`，或从 `Others/` 移动到 `Animals/`；
   - 系统再次扫描时无法识别其与历史记录的关联，导致旧记录沦为死数据（Ghost Record），而新文件被当成从未打标的裸图片重新初始化，人工复核心血彻底丢失。
2. **多批次导出存在重复使用风险（“跨包串图”）**：
   - 在先后导出 Main 关卡、Daily 日历、Event 限时活动或 Collection 图集时，运营人员难以快速获知哪些素材已经被消耗、哪些仍是库存新图；
   - 一旦某张图片被改名或移动，更容易被无意识地二次导出到不同的数据包中，损害玩家体验。

---

## 二、 架构原则：以图片源目录 (Source Directory) 为唯一锚点

所有的图库级业务数据、元数据和已使用状态，**必须且只能以「图片源目录」为唯一基准**：

```
📁 C:\Home\Temp\Jigsaw_Organized\  (源目录 srcDir - 独立自包含工作区)
  ├── 📄 tags.json        <- 分类标注与图片元数据 (注入 hash 字段)
  ├── 📄 exported.json    <- 已导出/已使用状态账本 (以 SHA-256 为主键)
  ├── 📁 Animals/
  └── 📁 Flowers/
```

- **隔离性保证**：切换源目录即代表切换独立的图库仓库（Workspace）。A 库导出了，不影响 B 库；源目录打包拷贝至其他机器，打标与导出记录天然完整保留。
- **职责分离**：
  - `tags.json`：记录素材属性（标签、宽高、格式、内容描述、内容 Hash）；
  - `exported.json`：记录流水线发布状态（被哪个模块导出过、导出时间、目标关卡号/版本/活动ID等）。重置导出历史只需操作 `exported.json`，绝不会损毁 `tags.json`。

## 三、 性能实测与算法选型：全量 SHA-256 硬件加速

在真实图库 `C:\Home\Temp\Jigsaw_Organized`（25,428 张图片，平均单张 1.8 MB）上实测数据：
- **SHA-256 单线程速率**：**600 张/秒 (1,070 MB/s)**；
- **SHA-256 8 线程并发**：**2,136 张/秒 (3,727 MB/s，1,000 张图仅需 0.46 秒)**；
- **现代 CPU 硬件支持**：Intel/AMD CPU 原生集成 SHA-NI 硬件指令集，SHA-256 速率甚至显著高于传统 MD5，且抗碰撞性极强。

### 增量 Hash 缓存机制 (Smart Incremental Hashing)
为了确保 25,000+ 级别图库在日常扫描中实现 **毫秒级秒开**：
1. **未变动图片（命中率 99%+）**：对比磁盘文件的 `mtime`（修改时间）与 `size`（文件大小），若相对路径匹配且 `mtime + size` 一致，直接复用 `tags.json` 中已有的 `hash`，耗时 **0 毫秒**；
2. **新增/变动图片**：仅针对新入库或内容发生变更的文件并发计算 SHA-256，耗时在毫秒级以内；
3. **初次冷启动扫描**：通过多线程并发，25,000 张图全量生成 Hash 仅需约 10 秒，完成后一次性固化。

## 四、 改名与移动的自动认领与继承引擎 (Auto-Reconciliation Engine)

扫描目录时，系统自动执行对齐算法：

```
                    扫描磁盘上的实际图片
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
    路径依然匹配的旧图片               发现新路径的文件 (new_files)
  (直接复用 tags 和 hash)                     │
                                     并发计算其 SHA-256
                                              │
                                     对比 tags.json 中
                                   路径已失效的孤儿记录
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    ▼                                                   ▼
         Hash 匹配到了旧记录！                               Hash 没匹配到旧记录
      (判定为：文件发生了改名或移动)                               (判定为：真正的新增图片)
                    │                                                   │
  自动更新 path / file 为新路径，                     正常按目录推断初始标签，
  100% 完整继承原有的 tags 与人工复核成果！              生成全新记录。
```

## 五、 已导出账本与防重闭环 (`exported.json`)

### 1. 数据模型
```json
{
  "version": "1.0.0",
  "updated_at": "2026-09-05T18:35:00Z",
  "total_exported": 150,
  "hashes": {
    "a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b57b277d9ad9f146e": {
      "path": "Animals/lion_01.jpg",
      "file_name": "lion_01.jpg",
      "file_size": 2048500,
      "export_type": "main",
      "target": "main/101.webp",
      "order": 101,
      "exported_at": "2026-09-05T18:30:00Z"
    }
  },
  "path_to_hash": {
    "Animals/lion_01.jpg": "a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b57b277d9ad9f146e"
  }
}
```

### 2. 双重防重过滤 (Dual-Level Deduplication)
- **第一层（内容 Hash）**：即使图片改名或挪动目录，同一内容绝不重复导出；
- **第二层（路径检索）**：前端渲染时基于 `path_to_hash` 瞬时标注已用状态。

### 3. 前端交互增强
- **卡片右上角徽章**：`[✔ 已导出: Main #101]`，轻微置灰已用图片；
- **工具栏过滤复选框**：`[ ] 隐藏已导出 (未用库存: 850)`，一键筛选纯新图；
- **导出弹窗防呆开关**：`[✔] 自动排除已导出的图片 (推荐)`，选图打包自动排重。
