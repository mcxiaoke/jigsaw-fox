# Studio 变更日志 2026-09-09

## tags.json 手动增量(delta)：type=manual 权威 + 自动保存 + 缩略图区分
- **type="manual" 权威标识（定稿）**：`save_tags_file` 落盘的 delta 一律写 `"type":"manual"`。`manual_tags` 无论真实标签还是 `["Others"]`（显式清空/未分类，与空数组等价收口为 `["Others"]`）都视为人工指定，所有下游**禁止**用目录名自动推断覆盖。
- **save 判定强化**：新增 `is_manual` 前端标记，只要该记录被用户显式操作（含"清空一个本就推断为 Others 的图"这类 no-op、以及"确认与目录推断相同"的 tag）就无条件落盘；`differs/has_text` 保留为**非前端生产者的安全网**。`normalize_records` 列表格式也透传 `is_manual`，保证导出 `tagsRecords` 路径不丢标识。
- **手动权威全链路**：`merge_scanned_images` §4.5 对齐遇到手动记录时**永不覆盖手动成员**、自动副本对齐到手动标签；hash 继承 donor **手动优先**于自动；`normalize_records(delta)` 置 `is_manual=True`。
- **exporter 修复（含此前漏洞）**：`main_exporter` 兜底改为 `if not tags and not is_manual` 才路径推断。手动清空为 `[]`/`Others` 的记录绝不被 re-derive（堵住"手动清空又被目录名重新分类"的问题）。
- **自动保存**：前端在唯一改标签入口 `applyTags` 置 `is_manual=true` 并触发 `scheduleAutoSave()`（600ms 防抖、静默落盘）；手动"保存 tags.json"按钮保留作兜底。用户改完即自动持久化，杜绝"忘了点保存"。
- **缩略图区分自动/手动**：网格卡片中 `item.is_manual` 时渲染 `✍️ 手` 徽标 + `.card-tags` 左侧橙色mark线（`studio.css`），一眼区分自动 tag 与手动(权威) tag。
- **前端内存 tag 操作审计修复**：① `batchSetReviewed`/`toggleViewerReview` 原先直接改 `review_required` 不置 `is_manual`、不自动保存 → 复核状态不落盘；现走"置 `is_manual` + `scheduleAutoSave()`"。② 自动保存原本把全量重对象 `records.value` 塞进请求体 → 新增 `buildSaveRecords()` 瘦身载荷（path/hash/tags/is_manual/review_required/subject/scene/reason）。③ 自动保存失败静默吞错 → 改为失败一律 toast 提示（防手动 tag 静默丢失）。已用 `node --check` 验证 JS 语法。
- **测试**：新增 `test_manual_cleared_to_others_not_overridden`、`test_manual_flag_persists_noop_clear`、`test_backend_manual_tag_operations`，校验手动 Others 不被覆盖、no-op 手动落盘、覆盖/追加/移除/重置/多图多次操作后手动不变量保持、`type`/`manual_tags` 落盘正确。前后端边界：前端仅改内存 records，落盘/导出权威由后端 `save_tags_file`/`merge_scanned_images`/`main_exporter` 把关，单测在后端层覆盖。`python -m unittest studio.test_studio` **46 项全部通过**。
- 设计文档已更新 schema 至 `type="manual"`，并转为"已落地"状态。

## tags.json 改为手动增量(delta)存储（只存人工打标）
- **背景**：原 `save_tags_file` 全量落盘，目录名自动推导的标签(Cats->Pets)及可重算元数据(size/mtime/format)也一并写入，文件大且 diff 不清晰。
- **核心改动**：`core/tags_manager.py` 重写 `save_tags_file` 为增量裁剪——仅持久化「人工打标/复核」的记录，返回 `(ok, filepath, saved, auto_skipped)`：
  - 目录名自动基准(`guess_tags_from_path`)与最终标签一致、且无 `subject/scene` 人工备注 → 跳过(计入 `auto_skipped`)，读取时由扫描/merge 重算；
  - **hash 身份 + 一旦手动永不自动归零**：新记录满足「标签≠基准 或 致 subject/scene」才落盘；已是 delta(按 hash 键)则始终保留/更新，即使改回与基准一致也不被裁掉；
  - 新格式：`{"$schema":"jigsaw-tags-delta-v1","key":"hash","records":[{path,hash,sha1,manual_tags,review_required?,subject?,scene?,reason?,updated_at}]}`；
  - 自动 records 的 `reason`(merge 写入的"智能推断/继承")不再作为手动判定依据，人工文本仅看 subject/scene。
- **读取兼容**：`normalize_records` 新增 delta 格式判定与解析（`manual_tags` 即该记录最终有效标签，整体覆盖目录基准），返回 `fmt_name="delta"`；旧全量格式只读兼容保留。主链路 `_handle_scan -> merge_scanned_images` 仍为唯一 guesser，自动图每扫重猜，无重复 guess。
- **前端/服务端适配**：`server.py _handle_post_tags` 返回 `{saved, autoSkipped}`；`static/js/app.js` 保存 toast 显示「手动 N 条（自动识别 M 条未落盘）」。
- **测试**：`test_studio.py` 更新 `test_scan_and_tags_manager`（自动裁剪近空、手动落盘、delta 读回），新增 `test_manual_tag_never_auto_reset`（hash 身份 + 永不自动归零）。`python -m unittest studio.test_studio` 43 项全部通过。
- 设计文档：`studio/docs/tags-delta-store-design-20260909.md`（迁移/精简流程因未正式使用、无手动 tags 延后）。

## P3 导出可靠性加固（先记账后交付 + 幂等 + 事件流）
- **先记账后交付**：导出账本记录统一前移到 outDir 拷贝之前（release 镜像完成后立即落账）。覆盖 `main_exporter`、`daily_exporter`、`pack_exporter_base`（event/collection），避免"图片已交付但账本未记"导致同一原图被重复使用。
- **幂等记账**：`exports_ledger.append_records()` 以 `(module, logicalId, revision)` 为唯一键去重，同一批次中断后重跑不会产生重复账本记录。
- **账本事件流**：新增 `.studio/ledger/exports_events.jsonl`（append-only），记账先追加事件再物化 `exports.json`；`exports.json` 损坏或缺失时 `_try_rebuild_from_events()` 全量重放重建账本，不再依赖快照。
- **结构化审计**：`workspace.py` 新增 `_append_structured()`/`record_audit()`，并升级 `log_export()` 为结构化写入（scope/entity/after/result）；导出与 tags 保存均输出结构化审计事件。

## 修复扫描哈希误判 + 账本快照备份
- `core/scanner.py`：图片缓存命中判定改用纳秒级 mtime（`st_mtime_ns`），`get_image_info` 与 `_worker` 两处统一。修复「同一秒内修改且大小相同」的文件被误判为未变、复用旧内容哈希的问题，避免哈希污染导致质检/去重/导出查重/账本 sourceHash 错位。升级后首次扫描会全量重算一次哈希（更安全），之后稳定命中。
- `core/exports_ledger.py`：新增 `backup_ledger_snapshot()`，将权威账本复制为带日期时间后缀快照（`.studio/ledger/backups/exports-YYYYMMDD-HHMMSS.json`），默认仅保留最近 30 份；账本 JSON 损坏被重置后可手工 copy 覆盖回滚历史。
- `server.py`：扫描接口在每次扫描结束后自动调用 `backup_ledger_snapshot(root)` 备份账本快照（失败仅告警，不影响扫描）。

## 修复 TestDuplicateHandling 五处失败
- 根因：`scanner.IGNORE_DIRS` 含 `temp`（大小写不敏感），测试夹具把重复副本放在 `Temp/` 目录下被扫描忽略，导致只发现 2/3 张图、重复组检测失效。
- 修复：`test_studio.py` 将测试副本目录由 `Temp/` 改为 `Copies/`（避开被忽略的目录名），重复图片仍能被正确识别。不改动 scanner 的 `temp` 忽略设计。
- 修复后 `python -m unittest studio.test_studio` 42 项全部通过。
