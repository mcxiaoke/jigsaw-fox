# Studio 变更日志 2026-09-09

## P3 导出可靠性加固（先记账后交付 + 幂等 + 事件流）
- **先记账后交付**：导出账本记录统一前移到 outDir 拷贝之前（release 镜像完成后立即落账）。覆盖 `main_exporter`、`daily_exporter`、`pack_exporter_base`（event/collection），避免"图片已交付但账本未记"导致同一原图被重复使用。
- **幂等记账**：`exports_ledger.append_records()` 以 `(module, logicalId, revision)` 为唯一键去重，同一批次中断后重跑不会产生重复账本记录。
- **账本事件流**：新增 `.studio/ledger/exports_events.jsonl`（append-only），记账先追加事件再物化 `exports.json`；`exports.json` 损坏或缺失时 `_try_rebuild_from_events()` 全量重放重建账本，不再依赖快照。
- **结构化审计**：`workspace.py` 新增 `_append_structured()`/`record_audit()`，并升级 `log_export()` 为结构化写入（scope/entity/after/result）；导出与 tags 保存均输出结构化审计事件。

## 修复扫描哈希误判 + 账本快照备份
- `core/scanner.py`：图片缓存命中判定改用纳秒级 mtime（`st_mtime_ns`），`get_image_info` 与 `_worker` 两处统一。修复「同一秒内修改且大小相同」的文件被误判为未变、复用旧内容哈希的问题，避免哈希污染导致质检/去重/导出查重/账本 sourceHash 错位。升级后首次扫描会全量重算一次哈希（更安全），之后稳定命中。
- `core/exports_ledger.py`：新增 `backup_ledger_snapshot()`，将权威账本复制为带日期时间后缀快照（`.studio/ledger/backups/exports-YYYYMMDD-HHMMSS.json`），默认仅保留最近 30 份；账本 JSON 损坏被重置后可手工 copy 覆盖回滚历史。
- `server.py`：扫描接口在每次扫描结束后自动调用 `backup_ledger_snapshot(root)` 备份账本快照（失败仅告警，不影响扫描）。

## 修复 TestDuplicateHandling 五处失败
- 根因：`scanner.IGNORE_DIRS` 含 `temp`（大小写不敏感），测试夹具把重复副本放在 `Temp/` 目录下被扫描忽略，导致只发现 2/3 张图、重复组检测失效。
- 修复：`test_studio.py` 将测试副本目录由 `Temp/` 改为 `Copies/`（避开被忽略的目录名），重复图片仍能被正确识别。不改动 scanner 的 `temp` 忽略设计。
- 修复后 `python -m unittest studio.test_studio` 42 项全部通过。

## 质检全量化
- 网页批量质检由每次仅 500 张改为全量处理。
- `core/cache_db.py`：`get_unscored_items` 支持 `limit<=0` 返回全量，与 `get_all_items` 对齐。
- `server.py`：`_handle_post_quality_batch` 中 `limit<=0` 表示全量，`>0` 才截断（上限 2000）；后台 worker 仍按子批排队处理，全量不阻塞。
- `static/js/app.js`：`triggerBatchQuality` 请求传 `limit=0` 启用全量。
