# Studio 变更日志 2026-09-09

## [Studio] Review 中优先级四项：批量防呆确认 + cancelled 状态 + fatal 降级 + 日志面板全面接入

### #5 批量打标 >20 张二次确认（`app.js`）
- `batchSetTag` / `batchRemoveTag` / `batchClearTags`：选中超过 20 张时弹 `window.confirm` 二次确认，明示影响张数与动作语义（覆盖会清除原标签 / 重置为 Others）；`batchAddTag` 因只追加不动原标签不加确认。

### #8 质检取消改为 cancelled 正常态（`server.py` / `app.js`）
- `_job_finish` 新增 `cancelled` 参数，`_run_quality_job` 取消分支改走 `state="cancelled"`（不再用 `error="cancelled"` 伪装失败）。
- 前端轮询识别 `cancelled` 终态（兼容旧 error="cancelled" 字符串），toast 显示"质检已取消"而非红色"质检失败"。端到端验证：cancelled 状态经 HTTP 快照正确透出。

### #12 fatal 守卫降级 + api.js 统一 JSON 兜底（`index.html` / `app.js` / `api.js`）
- `renderFatalError` 全屏拦截范围收窄到**挂载完成前**（`__STUDIO_APP_MOUNTED__` 标记由 app.js mount 后设置）；挂载后的 window.error / unhandledrejection 降级为 StdLog 记录，不再全屏盖掉打标界面。
- `api.js` 新增 `parseJson(res, context)` 公共兜底：所有 `res.json()` 调用点改造，非 JSON 响应（代理错误页/HTML）抛出含 HTTP 状态码的可诊断错误；`fetchJobStatus` 非 JSON 时静默返回 `{found:false}` 由轮询重试兜底；`cancelQualityJob` 加 catch。此前仅 `deleteImage` 有兜底。

### 日志面板全面接入（`app.js`）
- 新增 `stdError` / `stdWarn` / `stdInfo` 助手：双写 StdLog（右下角"📜 日志"面板，环形缓冲 500 条）与浏览器控制台；12 处 `console.error/warn` 全部迁移，前端 error/warn 不再只存在于 DevTools。
- 关键操作 info 埋点：扫描完成、tags 落盘、批量质检启动/收尾、导出启动/成功、批量打标 Set/Clear、删除素材。
- `showToast` 升级支持级别：error 红 8s / warn 橙 5s（均可手动关闭，新增 toast-close 按钮 + 级别样式）/ info 深色 2.5s；error/warn toast 同步写入 StdLog。13 处失败提示调用升级为对应级别。

### 测试基建加固（`test_frontend.py`）
- 修复无头挂载冒烟测试的既有缺陷：固定 1600ms 采样改为**轮询等待 `__STUDIO_VM__` 就绪（最多 12s）后再采样**，消除高负载下 20% 左右的假失败（实测 6/6 稳定通过）。

### 验证
- 全套 70 个测试通过（test_studio 46 + image_proc/ledger/workspace 22 + frontend 2）；`node --check` × 3 / `py_compile` 通过；所有改动行尾归一化 LF。

## [Studio] Review 高优先级四项修复：质检失败可见化 + 轮询自愈 + tags 损坏保护 + 禁止评估器降级

### #1 质检批次静默失败可见化（`server.py`）
- `_run_quality_job` 新增 `failed` 计数与 `consecutive_batch_failures`：整批评估失败时进度照走但计入失败，job 日志输出 warn 行；**连续 2 个整批全失败即中止任务置 error**（提示检查 OpenCV/Pillow 环境），绝不伪装成"质检完成"。
- `_job_register`/`_job_progress`/`_job_snapshot` 增加 `failed` 字段透出；最终汇总显示"质检完成: N/M 张 (其中 X 张评估失败，无评分数据)"。
- 前端 `qcProgress` 带 `failed`，进度条旁显示"失败 N"（橙色）。

### #2 轮询失败自动重试 + 一键重连（`app.js` / `index.html`）
- 质检与导出两侧轮询：网络错误不再 `return` 静默断链——连续失败计数（3s 间隔 × 10 次才判死），期间 toast 显示重试进度；判死后 UI 出现"🔄 重新连接质检/导出任务"按钮，点击重新挂载轮询（后端 clientTaskId 支持）。
- 导出侧重连钩子 `exportPollReconnector` 由 `runExport` 注入当前任务闭包，setup 级 `reconnectExportPoll` 供模板调用。

### #3 tags.json 损坏保留现场 + 告警（`tags_manager.py` / `server.py` / `app.js`）
- `save_tags_file` 读取旧文件失败时：损坏文件重命名为 `tags.json.corrupt-<ts>` 保留现场，日志 error，并通过新增可选参数 `warnings_out` 透出告警（4 元组签名不变，测试兼容）。
- `/api/tags` 响应带 `warning` 字段；前端保存后如有告警以 `⚠` 前缀 toast 展示（不再静默丢失手工标注权威标记）。

### #4 禁止质检评估器降级，启动时强校验环境（`server.py` / `quality_evaluator.py`）
- `run_server` 前新增 `_require_export_environment()`：当前解释器必须同时具备 **opencv-python + numpy + Pillow**，缺失直接打印诊断信息（含 pip 安装命令与 venv 解释器路径建议）并 `SystemExit(1)`。
- `evaluate_image` / `evaluate_images_batch` 删除 Pillow 降级路径：cv2 与 venv 子进程均不可用时抛 RuntimeError（评分口径不一致的静默降级是分数漂移根因）。`_evaluate_with_pillow` 保留但不再被统一入口调用。
- 验证：无 cv2 的 Python 启动 server 被拦截退出（exit 1，输出修复指引）；venv 解释器（cv2 5.0.0）正常。

### 验证
- `test_studio`(46) / `test_image_proc` + `test_ledger` + `test_workspace`(22) 全部通过（venv 解释器）；`node --check` + `py_compile` 通过；`test_frontend` 挂载冒烟通过（期间修复 `reconnectExportPoll` 作用域错误与误入的 TS 类型标注）。

## [Studio] Review 修复：导出 fail-fast + 前端脏保护 + 分页性能 + tagCounts 正交化

### 数据可靠性（后端导出引擎）
- **转码失败中止整批**：`main_exporter.py` 转码循环改为先检查失败——任一张失败即 RuntimeError 中止，列出全部失败明细，不再写入批次 JSON/index.json/账本（此前失败图仍记账，会被"选未导出"永久排除，构成不可恢复丢图）。`pack_exporter_base.py` / `daily_exporter.py` 删除"转码失败静默回退写入未转码原图"分支（Event/Collection 继承基类自动获得修复）。
- **账本写入失败中止交付**：三个导出器的账本 `except: warn` 全部改为 raise——账本是防重复发布与 revision 推算的唯一权威，写失败严禁继续拷贝 outDir 与更新 manifest。错误信息注明"未交付、可直接重试"（账本 append_records 幂等，重试安全）。
- **index/manifest 解析失败禁止静默重置**：`main/pack/daily` 的 index.json 解析失败或根节点非对象时中止（此前静默清零会导致版本归零、批次重号覆盖历史）；`manifest_manager.py` 损坏时不再"重新初始化"丢掉其余所有模块路由，改 fail-fast。

### 数据可靠性（前端）
- **未保存修改保护**：新增 `unsavedCount` 脏计数（applyTags 全路径 +1，保存成功清零）；`beforeunload` 拦截关闭/刷新；扫描目录前脏状态弹确认；自动保存失败指数退避自动重试（1s→5s→15s→30s），不再仅 toast 2.5s；保存按钮显示未保存条数/重试中状态（橙色描边）。
- **tagCounts 正交化**：过滤链拆分为 `preTagFilteredRecords`（待复核/重复/隐藏已导出/品质/搜索，不含 activeTag）→ `tagCounts` 计数 + 侧栏"全部"计数；`filteredRecords` 仅在其上叠加 activeTag 过滤+排序。修复"选中任一 tag 后其它分类计数全部归零"；品质/搜索等过滤仍实时联动计数。侧栏"全部 All"计数从 `records.length` 改为 `preTagFilteredRecords.length`，与各 tag 口径一致。

### 性能（前端）
- **卡片分页**：网格默认每页 500 张（可选 200/500/1000/全部），分页条吸顶支持跳页；筛选/排序/搜索变化自动回第一页。
- **搜索防抖**：搜索框 250ms 防抖（`searchInput` → `searchQuery`），不再每键触发全量重算。

### 其他
- 编辑工具行尾污染修复：7 个文件 CRLF → LF 还原（仓库 `core.autocrlf=false`，原文件为 LF）。
- 验证：`test_studio`(57) / `test_ledger` / `test_workspace` / `test_image_proc`(11) / `test_frontend`(2) 全部通过；node --check / py_compile 通过。

## [Studio] 品质过滤改为复选框 + 排序方向切换 + tagCounts 联动过滤

- **品质过滤**：删除原品质下拉框 + 分数 min/max 输入框 + 5 个快捷按钮，替换为 6 个品质复选框（S/A/B/C/F/未质检），各带数量标签。全不选 = 全部展示，选一个或多个 = 仅显示对应品质。数量来自服务端 `qualitySummary` 全量统计，不受复选框自身过滤影响。
- **排序方向**：排序下拉旁新增 ↑↓ 方向切换按钮，`sortOrder` 默认值从 `"asc"` 改为 `"desc"`（得分排序默认高→低）。按钮 title 同步更新。
- **tagCounts 联动过滤**：`tagCounts` computed 数据源从 `records.value`（全量）改为 `filteredRecords`（过滤后），左侧侧边栏各 tag 的计数会随品质复选框、搜索、隐藏已导出等过滤实时联动。伪分类（已导出、不合格、重复）计数仍基于全量 `records.value`，本次未改动。
- 涉及文件：`studio/static/index.html`、`studio/static/js/app.js`。后端 `server.py` 无改动。

## content box 算法：sal90 落地 + fusion（std25∪sal90）融合默认
- `studio/core/crop_compute.py`：新增 `saliency_content_box`（显著性能量 q=90 掩膜跨度 + pad，空掩膜/均质自动回退整图），并将 `fusion_content_box` 设为默认——同图分别算 sal90 与 std25（细节纹理），两框相交时逐边取并集（任一算法保留的边不丢弃），不相交时回退取面积较大者；docstring 含算法语义与实测依据。
- `studio/core/quality_evaluator.py` / `studio/core/image_proc.py`：质检 `_compute_smart_crop` 与导出 `trim_background` 的 content_box 由 usm 细节阈值法 → sal90 → `fusion_content_box`，两条链路口径统一。
- 验证：71 张 Animals 样库 fusion 与手工并集逐字节一致 71/71，34 张有并集增益（典型 fox 顶部 738→524）；py_compile 通过。
- 注意：质检详情走 hash 缓存，需清空质量缓存/重新质检才刷新 viewer 框，导出链路实时生效。
