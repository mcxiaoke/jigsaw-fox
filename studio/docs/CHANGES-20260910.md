## [Studio] Event/Collection 封面压缩：限幅裁切 + 长边 1080（2026-09-10 17:35）

### 问题
- `pack_exporter_base.py` 封面用 `convert_image` 纯转码生成，不缩放不裁剪：封面 = 第一张源图原尺寸，超高清源图导出的封面动辄数十 MB。

### 修复（方案 B 折中：正常图不裁、异形图裁到限幅边界）
- `core/image_proc.py` 新增 `make_cover_image(src, dst, *, quality=70, long_target=1080, ratio_clamp=2.0)`：
  - `compute_content_box` 内容感知定位主体框；
  - 框长宽比在 `[1/clamp, clamp]` 内 → 不裁，仅长边缩放 1080（`resize_long` 只缩不放）；
  - 超宽裁到 `clamp:1`、超高裁到 `1:clamp`，裁切窗口用 `smart_aspect_crop_box` 显著性滑窗对准主体；
  - WebP 编码落盘，`quality` 与导出面板同源（`resolve_quality` 结果）；
  - numpy/裁切算法缺失时降级为纯转码（等同旧行为）并返回 `crop_mode=degraded_convert_only`，不阻断导出。
- `exporters/pack_exporter_base.py`：封面生成改调 `make_cover_image`；新增封面规格日志（输出尺寸/裁切模式）与降级 warn。
- 效果：封面输出恒定在长边 1080（约 1080×540 ~ 1080×1080），体积从数十 MB 降到 KB 级。

### 测试
- `test_image_proc.py` 新增 `TestMakeCoverImage`：正常图不裁（比例保持）、超宽裁 2:1、超高裁 1:2、降级路径；全部通过（15 tests OK，1 skip 为环境预期）。
- 全套件 `discover` 110 tests：仅 `test_frontend` 无头挂载 2 例失败，为 master 存量环境问题（stash 后复测确认），与本次改动无关。

## [Studio] .studio 目录 Git 版本化守卫：导出/回滚节点自动 commit（2026-09-10 14:15）

`.studio/` 元数据（tags.json、账本、审计流水）纳入独立 git 仓库管理，repo 建在 `src_dir/.studio` 内自包含，不扫描素材主体。

### 新增 `core/git_guard.py`
- 三种守卫模式（`.studio/git_guard.json` 配置，损坏/缺失回退 `auto`）：`off` 不参与、`auto`（默认）导出前自动 checkpoint + 导出/回滚后自动 commit、`strict` 在 checkpoint 失败且仍有未提交变更时拦截导出。
- 幂等 `ensure_repo`：git init + `.gitignore`（cache/ staging/ release/，规避 SQLite WAL 抖动破坏 clean 语义）+ `.gitattributes`（`* -text` 防行尾漂移）+ 局部身份配置（user.name=studio / autocrlf=false / gc.auto=0）+ 初始导入 commit。
- GitPython 优先（venv 已装 3.1.62），异常/超时（10s）降级 git CLI，再不可用则 no-op + warning；所有异常不向上冒泡，绝不阻塞导出/回滚主流程。
- commit 消息规范：`checkpoint(pre-export): <type> (auto)` / `export(<type>): <n> images` / `export(<type>): failed after checkpoint (auto)` / `rollback(<modules>): op=<opId> <reason>`；clean 跳过不产生空 commit。
- 日志可观测性（二次补充）：初始化（首次/已存在）、模式读取（非法值 warning）、commit 均有 `[GIT_GUARD]` 前缀日志；新增 `describe_status()` 单行状态摘要，`/api/scan` 完成时输出 `[GIT_GUARD] 已纳管 (mode=…) | 工作区… | 最近: …`（纯只读，不产生 git 操作）。

### `server.py` 挂接
- `_handle_export`：正式导出 validate 前确保 repo + guard（strict 拦截返回 400）；成功/失败（ValueError/Exception）收尾 commit；试导出（trial）零 git 操作。
- `_handle_rollback`：`undo_op` 成功且非 dryRun 后 commit；dryRun 不产生任何 git 操作。

### 新增 `test_git_guard.py`（13 项）+ 设计文档 `docs/git-guard-design-20260910.md`
覆盖幂等初始化、ignore 生效性、checkpoint 空提交跳过、auto 化解 dirty、strict 拦截、模式容错、消息断言、仓库损坏降级、GitPython 缺失 CLI fallback。

**回归**：全套 106 项测试通过（基线 93 + 新增 13，无回归）；新文件 UTF-8 + LF；设计文档含两轮自审记录（消息规范与实际数据结构对齐、守卫异常不冒泡）。
