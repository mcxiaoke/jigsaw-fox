## [Studio] git guard ignore 文件改为托管区校准 + ledger/backups 入库泄漏修复（2026-09-10 19:01）

### 问题一：用户手改 .gitignore 被静默抹掉
- `core/git_guard.py` 的 `_write_once` 是"内容≠模板就整体覆盖"，且在**每次** `ensure_repo`（每次正式导出）都执行、不区分首次/非首次。
- 后果：用户追加的忽略规则在下次导出即被抹掉，并由后续 checkpoint commit 记成 revert，表现为"改了又消失"。实测仓库（`F:\Pictures\JigsawGame\Source\.studio`）：17:43 用户手加的 5 行被 `28336ed rollback(...)` 顺带提交，17:46 `1003097 checkpoint(pre-export)` 即被 revert。

### 问题二：忽略规则被抹掉后 zip/webp 被提交进仓库
- `ledger/backups/` 从不在模板忽略范围内，而 `git add -A` 会提交 ignore 之外的一切。
- 实测已入库：`ledger/backups/trashed-op_20260910_093838668/collections/colorful-ufferflies-001.zip`（2.1MB）、`...001.webp`（52KB）、`ledger/backups/exports-*.json` 共 23 份（~5MB 累计），均由 `1003097` / `d904b2f` 引入；`.git` 已达 3.6MB，且每次导出仍会新增 1~2 份 300KB 账本快照（当前已有 4 份未被忽略）。

### 修复
- `core/git_guard.py`：`_write_once` → `_calibrate_managed_file`，引入托管区标记
  `# >>> studio git guard managed, do not edit >>>` / `# <<< studio git guard managed <<<`：
  - 含标记：只替换标记之间的内容（模板升级可下发），标记之外的用户行**一律保留**；
  - 无标记老文件：原有内容全保留，托管区追加到末尾，不丢任何行；
  - 无变化不落盘，保持 mtime 稳定；不再存在"整文件覆盖"路径。
- 托管区新增 `ledger/backups/`（账本快照 + 回滚 trashed 产物）。

### 测试
- `test_git_guard.py` 新增 4 例：`ledger/backups/` 被忽略不产生 dirty；用户规则跨 `ensure_repo` 保留；无标记老文件内容不丢且二次校准幂等；模板升级时标记外用户规则保留。全套 17 tests OK。

### 遗留（需用户授权后执行，涉及 .studio 仓库的 git 状态变更）
- 已入库的 zip/webp/23 份账本快照需 `git rm --cached` 才能从跟踪中摘除（ignore 对已跟踪文件不生效）；历史 blob 不重写。
